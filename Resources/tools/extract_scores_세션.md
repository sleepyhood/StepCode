### 📋 데이터 추출 및 통계 생성을 위한 계획안

사용자님의 목적(특정 수강생 명단의 성적 산출 및 공지)을 고려할 때, 독립적인 파이썬 스크립트를 작성하는 것이 가장 효율적입니다.

#### 1. 환경 설정 및 준비
*   **대상 설정**: 대상 사이트의 `BASE_URL`과 관리자 계정 정보 정의.
*   **인증 처리**: 세션을 유지하거나 필요한 쿠키 값을 설정하여 권한 획득.
*   **대상 문제군 정의**: 추출하고자 하는 문제 ID 패턴(Prefix) 또는 범위(Range) 설정.

#### 2. 대상 학생 명단 확보
*   사용자가 제공한 **학생 ID 리스트**를 입력받아 타겟팅 조회 준비.

#### 3. 개별 학생 데이터 수집 (반복문)
*   ID 리스트를 순회하며 프로필 API(`/api/profile?username={username}`)를 호출.
*   응답 JSON에서 `data.oi_problems_status.problems` 내부 파싱.
*   **필터링**: 목표로 하는 ID 패턴과 일치하는 데이터만 추출하여 `{문제ID: 점수}` 형태로 저장.

#### 4. 데이터 구조화 (Pivot Table 형태)
*   **행(Row)**: 학생 이름/ID (`username`)
*   **열(Column)**: 문제 ID 리스트 (정렬된 상태)
*   **값(Value)**: 해당 문제의 `score`

#### 5. 결과 출력 및 분석
*   **Excel 저장**: 수집된 데이터를 엑셀로 내보내어 시각적 확인 가능하게 구성.
*   **점수 통계**: 문제별/학생별 총점, 평균, 석차 등을 계산하여 요약 리포트 제공.

### 🛠️ 프로젝트 상세 현황

#### 1. 프로젝트 목적
*   **목표**: 특정 도메인에서 **지정된 학생 명단(학번/ID)**을 대상으로, 특정 문제군에 대한 점수 현황을 엑셀로 추출하고 성적 통계를 산출함.
*   **대상**: 사용자가 입력한 특정 수강생 리스트 및 특정 문제 접두사.

#### 2. 주요 작업 결과물
*   **메인 스크립트**: `extract_scores.py` (인증, 명단 확보, 점수 추출, 저장 통합)

#### 3. 현재 진행 상태 및 기술적 상세
*   **인증 로직**: 기존 프로젝트의 쿠키 정보를 재사용하거나 동적 입력을 통해 권한 획득.
*   **데이터 수집 방식**: 사용자 제공 ID 리스트를 통한 타겟팅 조회 방식.
*   **성능 최적화**: 호출 사이 지연 시간 및 `flush=True`를 통한 실시간 로그 출력 적용.

#### 4. 다음 단계 (Next Steps)
1.  **접두사/범위 확인**: 추출하고자 하는 실제 문제 ID의 정확한 패턴 확인.
2.  **대상 서버 설정**: 실제 운영 중인 사이트 도메인 및 계정 정보 반영.

### 🚀 고도화 개선 계획 (대학생 성적 공지용)

#### 5.1 엑셀(Excel) 시각화 및 가독성 강화
*   **포맷 전환**: CSV 대신 `.xlsx` 직접 생성 (`openpyxl` 활용).
*   **조건부 서식**: 점수 구간별 **초록(고득점) - 노랑(중간) - 빨강(저득점)** 그라데이션 자동 적용.
*   **결측치 처리**: 미제출 데이터를 `"미제출"` 또는 공백으로 표시하여 시각적 구분감 제공.

#### 5.2 환경 범용성 및 입력 편의성 (crawler_baekjoon_gui.py 스타일)
*   **동적 설정**: 실행 시 **사이트 주소(URL)**와 **관리자 계정**을 직접 입력받아 다양한 서버 환경에 대응.
*   **문제 구간 지정**: 시작~끝 번호를 입력받아 **데이터 유무와 상관없이 고정된 엑셀 컬럼** 보장.
*   **ID 리스트 입력**: 조회할 학생 ID 목록을 파일이나 텍스트로 입력받아 타겟팅 조회 (속도 향상).

#### 5.3 성적 분석 및 시각화 고도화
*   **분포 차트**: 별도 시트에 **성적 분포 히스토그램** 자동 생성.
*   **통계 자동화**: 총점, 평균, 석차 외에 **Pass/Fail 판정** 및 사분위수 통계 추가.

#### 5.4 실행 안정성 및 데이터 보호 (Robustness)
*   **중간 저장(Checkpoint)**: 대규모 인원 조회 중단 시 **마지막 지점부터 재시작** 가능하도록 설계.
*   **에러 로그**: 추출 실패 학생 목록을 `error_students.log`로 별도 관리.

#### 5.5 공지 자동화 및 보안
*   **피드백 자동 생성**: 유저별 취약 문제 요약 컬럼 추가.
*   **공지용 PDF**: 개인정보 보호를 위해 학번/성적만 남긴 **공지용 PDF 내보내기**.
*   **계정 보안**: 비밀번호 입력 시 마스킹 처리 및 `.env` 지원.
