사용자님의 목적(모든 학생의 특정 문제군에 대한 점수 통계 산출)을 고려할 때, 기존 API 서버 코드에 기능을 추가하기보다는 **별도의 독립적인 파이썬 스크립트를 작성하는 것이 훨씬 효율적**입니다.

이유는 다음과 같습니다:
1.  **일회성/배치 작업의 특성**: 실시간 웹 서비스 기능이라기보다는 데이터 분석 및 리포트 생성에 가깝기 때문입니다.
2.  **유연성**: 도메인이나 문제 ID 체계가 다른 '복제 사이트'를 대상으로 할 때, 기존 서버의 설정(Config)을 건드리지 않고 스크립트 내부에서만 파라미터를 조정할 수 있습니다.
3.  **성능 및 안정성**: 다량의 학생 데이터를 순회하며 호출해야 하므로, 웹 서버 스레드를 점유하지 않고 로컬에서 비동기 또는 루프 처리를 하는 것이 안전합니다.

### 📋 데이터 추출 및 통계 생성을 위한 계획안

#### 1. 환경 설정 및 준비
*   **대상 설정**: 복제된 사이트의 `BASE_URL`과 로그인 계정 정보(쿠키 획득용) 정의.
*   **인증 처리**: 기존 `login.py` 로직을 참고하여 세션을 유지하거나, 필요한 쿠키 값을 스크립트 상단에 설정.
*   **대상 문제군 정의**: 추출하고자 하는 문제 ID의 패턴(예: `ky_2026_01_26682_`) 설정.

#### 2. 학생 명단 확보
*   대상 사이트의 `/api/user_rank` 등을 호출하여 전체 학생의 `username` 리스트를 먼저 확보합니다.

#### 3. 개별 학생 데이터 수집 (반복문)
*   확보된 학생 리스트를 순회하며 각 학생의 프로필 API(`/api/profile?username={username}`)를 호출합니다.
*   응답 JSON에서 `data.oi_problems_status.problems` 내부를 파싱합니다.
*   **필터링**: `_id` 값이 목표로 하는 접두사(`ky_...`)로 시작하는 데이터만 추출하여 `{문제ID: 점수}` 형태로 저장합니다.
*   *주의: 서버 부하 방지를 위해 호출 사이에 짧은 지연 시간(time.sleep)을 추가합니다.*

#### 4. 데이터 구조화 (Pivot Table 형태)
*   **행(Row)**: 학생 이름 (`username`)
*   **열(Column)**: `ky_2026_01_26682_01`, `02`, `03`... (발견된 모든 관련 문제 ID)
*   **값(Value)**: 해당 문제의 `score`
*   데이터를 이차원 배열이나 Pandas DataFrame 형태의 구조로 모읍니다.

#### 5. 결과 출력 및 분석
*   **CSV/Excel 저장**: 수집된 행렬 데이터를 엑셀로 내보내어 한눈에 확인 가능하게 만듭니다.
*   **점수 카운트**: 각 문제(열)별로 점수가 100점인 학생 수, 평균 점수 등을 계산하여 요약 리포트를 출력합니다.
