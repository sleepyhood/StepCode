# 유니티 문제 풀이 정리 템플릿 규칙 (v3: 드래그&드롭/그래픽 매칭 포함)

> 원칙: **지문 → (자료/보기) → 내 선택 → 정답 → 해설**  
> 목표: 사람이 읽기 쉬우면서도, 추후 JSON 변환이 가능한 “구조 고정” 템플릿
> 작성 금지: 지문/보기/정답/해설 본문에는 `:contentReference[...]`, `oaicite`, `turn...` 같은 내부 표식(출처 토큰)을 절대 쓰지 않는다. 발견 시 삭제.

## 1) 공통 섹션 순서(모든 문항 동일)

1. 제목/메타

3. 자료(필요 시: 코드/오류메시지/이미지 설명)

### 3-5) 드래그&드롭 / 그래픽 매칭(Animator 상태 배치 등)

> 이미지 위 “빈 칸(드롭존)”에 텍스트 토큰(드래그 항목)을 배치하는 문제를 위한 규격


### 자료(이미지/그래픽)
- 이미지: (파일명 또는 캡처 설명)
- 드롭존(빈칸) 설명: (어느 위치의 빈칸인지 텍스트로도 식별 가능하게)

### 드래그 항목(토큰)
- `FastLand`
- `SlowFall`
- `JumpApex`
- `FastFall`

### 드롭존 목록(빈칸)
- Z1: Jump 정점(Apex) 상태 칸
- Z2: 느린 낙하(Slow Fall) 상태 칸
- Z3: 빠른 낙하(Fast Fall) 상태 칸
- Z4: 빠른 착지(Fast Land) 상태 칸

### 내 선택(배치 결과)
- Z1 ← `JumpApex`
- Z2 ← `SlowFall`
- Z3 ← `FastFall`
- Z4 ← `FastLand`

### 정답(배치 정답)
- Z1 ← `JumpApex`
- Z2 ← `SlowFall`
- Z3 ← `FastFall`
- Z4 ← `FastLand`

### 해설
#### 핵심 근거(3줄 요약)
1. Apex는 점프의 정점 구간으로 Slow/Fast 공통으로 수렴한다.
2. Apex 이후 낙하는 Slow/Fast 분기 상태로 이어진다.
3. 낙하 후 착지 상태(Land)로 연결되며, Fast 쪽은 FastLand가 대응된다.

#### 오답 포인트(헷갈리는 지점)
- `FastFall` vs `FastLand` 위치 혼동(낙하/착지 구분)
- `SlowFall`은 착지(SlowLand)가 아니라 낙하 상태임

## 4) JSON 변환을 위한 “필수 고정 규칙”

* 문항 제목은 반드시 `## [n번]`으로 시작
* `- 유형:` 라인은 항상 존재
* `### 지문`은 항상 존재
* `### 내 선택`은 항상 존재 (모르면 “미선택” 표기)
* `### 정답`은 항상 존재
* 드래그&드롭 유형은 **드롭존 ID(Z1, Z2...)를 반드시 명시**

  * (이미지 좌표가 없어도, 최소한 “Z1=어떤 칸인지” 텍스트로 식별 가능해야 함)
