# 입력

## 공통 원칙 (언어 무관)

### 리뉴얼 목표
1. 입력 단원은 **문법 재현(정확히 쓰기)** 을 최우선으로 한다.
2. Python/C/Java를 **동일한 문항 유형**으로 구성하고, 언어별 차이는 문법만 분기한다.
3. 핵심 검증은 `Code + Short`로 수행하고, `Trace/Grid`는 보조로 사용한다.

### 학습 개념(필수)
1. 한 줄 입력 파싱(공백 분리 + 형 변환).
2. 여러 줄 입력과 읽는 순서.
3. 문자열/정수 혼합 입력 처리.
4. 공백이 여러 개인 입력에서 안전한 분리.
5. 서식 출력(입력값을 형식에 맞게 재출력).

### 문항 구성 규칙
1. 세트당 `Code` 최소 2문항.
2. 세트당 `Trace/Grid` 1문항(보조).
3. 세트당 `입력 파싱 Code` 최소 1문항.
4. 세트당 `서식 출력 Code` 최소 1문항.
5. 단순 출력값 맞히기 문항은 세트의 절반 이하로 제한.

### Code 문항 고정 규칙 (입력 단원)
1. `Code` 문항은 가능한 한 **한 줄 작성**으로 고정한다.
2. 한 문항에서 한 기능만 검증한다.
   - 입력 한 줄
   - 출력 한 줄
   - 형 변환 한 줄
3. 제어문 전체를 한 줄로 쓰게 하지 않는다.
   - 입력 단원에서는 `if/for/while` 압축형 출제를 지양한다.
4. 문제 설명에 “한 줄로 작성”과 “작성 대상”을 명시한다.

### 언어별 변환 규칙
1. **유형/의도/정답 논리 동일**: 같은 세트 번호(b01~c01)는 같은 사고를 검증한다.
2. **문법만 변경**:
   - Python: `input`, `split`, `map`, `print`
   - C: `scanf`, `printf`
   - Java: `Scanner`, `System.out.printf/println`
3. 출력 형식과 채점 기준(공백/순서)은 동일 의미로 맞춘다.

## 세트 골격 (공통 템플릿)

### b01 (기초)
1. Trace/Grid: 한 줄 입력 2개 파싱 후 값/출력 기록.
2. Code: 정수 2개 입력 파싱 한 줄 작성.
3. Short: 출력 순서/토큰 재배치 판단.
4. Code: 서식 출력 한 줄 작성.
5. Short: 두 줄 입력 처리 결과.

### b02 (기초)
1. Trace/Grid: 여러 공백 입력 파싱.
2. Short: 문자열+정수 혼합 출력 형식.
3. Code: 둘째 줄 입력 파싱 한 줄.
4. Code: 다중 값 서식 출력 한 줄.
5. Short: 여러 줄 입력을 한 줄 출력으로 결합.

### b03 (기초)
1. Trace/Grid: 세 정수 입력 파싱/합 계산.
2. Code: 세 정수 입력 한 줄 작성.
3. Short: `split()` 이후 자료형 판단.
4. Code: 식 결과 서식 출력 한 줄.
5. Reverse: 출력/합으로 누락 입력 추론.

### c01 (챌린지)
1. Trace/Grid: 문자열 + 점수 2개(여러 공백 포함) 파싱.
2. Reverse: 식 출력으로 누락 입력 추론.
3. Code: 둘째 줄 점수 입력 한 줄.
4. Code: 이름+합계 서식 출력 한 줄.
5. Short: 공백 입력에서 값 개수 판단.

## 실제 세트 매핑

- Python 세트 파일:
  - `py_lv03_input_b01.json`
  - `py_lv03_input_b02.json`
  - `py_lv03_input_b03.json`
  - `py_lv03_input_c01.json`
- 향후 C/Java 이식 시에도 위 공통 템플릿과 동일한 골격으로 작성한다.
