### 개념 1) 컴파일러/인터프리터/헤더 기능 판별
- 개념 정의: 컴파일러, 인터프리터, 표준 헤더가 각각 어떤 계층에서 어떤 역할을 하는지 구분하는 개념입니다.
- 핵심 내용:
  - 컴파일러는 코드를 한 번에 번역해 실행 파일을 만듭니다.
  - 인터프리터는 코드를 읽으면서 바로 실행합니다.
  - 표준 헤더는 실행 도구가 아니라 함수/매크로 정보를 제공하는 선언 묶음입니다.
  - 헤더 문항은 대표 API 키워드로 기능을 연결하면 안정적으로 판별할 수 있습니다.
- 오답 포인트: `stdarg.h`를 예외 처리로 오해하거나, 번역 도구와 실행 방식을 같은 범주로 보면 오답이 발생합니다.

빠른 비교표:

| 항목 | 무엇을 하는가 | 문항에서 자주 나오는 표현 |
| --- | --- | --- |
| 컴파일러 | 소스 코드를 실행 파일로 번역한다 | 번역, 실행 파일 생성 |
| 인터프리터 | 코드를 읽으며 즉시 실행한다 | 한 줄 실행, 즉시 해석 |
| 표준 헤더 | 함수/매크로 선언 정보를 제공한다 | include, 라이브러리 기능 연결 |

핵심 매칭표:

| 헤더 | 핵심 기능 | 대표 키워드 |
| --- | --- | --- |
| `stdio.h` | 표준 입출력 | `printf`, `scanf` |
| `time.h` | 시간/날짜 처리 | `time`, `tm` |
| `assert.h` | 단정 검증 | `assert(...)` |
| `stdarg.h` | 가변 인자 처리 | `va_list`, `va_start` |
| `stddef.h` | 공통 타입/매크로 | `size_t`, `NULL` |

예시 (변형):
```c

#include <stdio.h>

int sum(int n, ...) {

    va_end(ap);

    printf("%d\n", sum(3, 2, 4, 6));
    return 0;
}
```

### 개념 2) `limits.h`와 `SHRT_MAX` 해석
- 개념 정의: 정수형 범위 상수와 필요한 헤더를 함께 해석하는 개념입니다.
- 핵심 내용:
  - `SHRT_*`는 `short`, `INT_*`는 `int`, `LONG_*`는 `long` 범위를 뜻합니다.
  - 범위 상수는 `limits.h`에서 제공되며, 상수 이름 자체가 자료형 정보를 포함합니다.
- 오답 포인트: `SHRT_MAX`를 `INT_MAX`와 혼동하면 선지 제거가 실패합니다.

직관 비유:
- 자료형은 크기가 정해진 저장칸입니다.
- `SHRT_MAX`는 `short` 저장칸에 들어갈 수 있는 최댓값입니다.

형식 규칙:
- 대회/학습 기준에서 `short`는 보통 16비트로 다룬다.
- 대표 범위는 `-32768 ~ 32767`이다.

핵심 상수표:

| 상수 | 의미 | 보통 16비트/32비트 환경 기준 값 |
| --- | --- | --- |
| `SHRT_MIN` | `short` 최솟값 | `-32768` |
| `SHRT_MAX` | `short` 최댓값 | `32767` |
| `INT_MAX` | `int` 최댓값 | `2147483647` |

![limits.h 상수군과 자료형 범위 연결 다이어그램](./data/theory/images/contest_w01_limits_constants_map.svg)

예시 (기본):
```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d\n", SHRT_MAX);
    return 0;
}
```
```io
input:
(없음)
output:
32767
```

예시 (변형):
```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d %d\n", SHRT_MIN, SHRT_MAX);
    return 0;
}
```
```io
input:
(없음)
output:
-32768 32767
```

예시 (함정):
```text
코드에 SHRT_MAX를 쓰면서 limits.h를 포함하지 않으면
컴파일 오류(미정의 식별자)가 발생할 수 있다.
```

### 개념 3) `short` 오버플로우와 정수 승격
- 개념 정의: `short` 식 계산에서 일어나는 `int` 승격과, 재대입 시 발생하는 경계 순환을 함께 이해하는 개념입니다.
- 핵심 내용:
  - `s + 1` 같은 식은 먼저 `int`로 승격되어 계산됩니다.
  - 대입이 없으면 승격 계산값이 그대로 출력됩니다.
  - `s = s + 1`처럼 다시 `short`에 저장하면 범위를 넘는 값이 순환됩니다.
  - 같은 식이라도 대입 유무와 갱신 횟수에 따라 최종 출력이 달라집니다.
- 오답 포인트: 계산 단계와 저장 단계를 섞거나, 2회 이상 갱신에서 중간 단계를 생략하면 오답이 발생합니다.

직관 비유:
- 계산은 큰 컵(`int`)에서 하고, 저장은 작은 컵(`short`)으로 다시 옮깁니다.

비교 체크표:

| 상황 | 계산 타입/저장 타입 | 추적 포인트 |
| --- | --- | --- |
| `printf("%d", s+1)` | 계산 `int`, 저장 없음 | 승격 계산값 그대로 출력 |
| `s=s+1; printf("%d", s)` | 계산 `int`, 저장 `short` | 저장 시 경계 순환 확인 |
| 2회 이상 재대입 | 계산/저장 반복 | 단계별 중간값 기록 필수 |

![short 승격 계산과 재대입 순환 흐름 다이어그램](./data/theory/images/contest_w01_short_promotion_assignment_flow.svg)

예시 (기본):
```c
#include <stdio.h>

int main(void) {
    short s = 32767;
    printf("%d ", s + 1);
    s = s + 1;
    printf("%d\n", s);
    return 0;
}
```
```io

(없음)
output:
32768 -32768
```

예시 (변형):
```c

    short s = 32766;
    s = s + 1;
    s = s + 1;
    printf("%d\n", s);
    return 0;
}
```
```io

(없음)
output:
-32768
```

예시 (함정):
```text
같은 식이라도 `printf("%d", s+1)`과 `s=s+1; printf("%d", s)`는 결과가 다를 수 있다.
```

5. 마지막에 경계값(최대/최소) 여부를 다시 점검한다.

## 초등 트랙 (ELEMENTARY)
<!-- audience:elementary -->
### 초등 포인트
- 개념 1의 용어 매칭 정확도를 먼저 확보합니다.
- 코드 추적은 경계값 1회 갱신까지 안정적으로 처리합니다.

### 초등 연계 실습
실습 목표:
- 헤더와 상수의 관계를 한 번에 설명합니다.

실습 문제:
```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d\n", SHRT_MAX - 2);
    return 0;
}
```

체크포인트:
1. 왜 `limits.h`가 필요한지 설명했는가?
2. `SHRT_MAX - 2`를 숫자로 검산했는가?

### 초등 오답 패턴
- 상수 이름은 맞게 고르고 헤더를 틀린다.
- 범위값을 외웠지만 문제 문장 키워드와 연결하지 못한다.

## 중등 트랙 (MIDDLE)
<!-- audience:middle -->
### 중등 포인트
- 개념 3에서 연산 타입과 대입 타입을 분리해 설명합니다.
- 헤더 판별 문항은 오답 선지 제거 근거를 1줄로 남깁니다.

### 중등 연계 실습
실습 목표:
- 대입 유무에 따른 출력 차이를 비교합니다.

실습 문제:
```c
#include <stdio.h>

int main(void) {
    short s = 32767;
    printf("%d ", s + 1);
    s = s + 1;
    printf("%d\n", s);
    return 0;
}
```

체크포인트:
1. 첫 출력과 둘째 출력이 다른 이유를 설명했는가?
2. "승격"과 "잘림"을 분리해 적었는가?

### 중등 오답 패턴
- `s+1`을 항상 `short` 계산으로 처리한다.
- 경계값 문항에서 초기값을 누락하고 중간 계산만 적는다.

## 고등 트랙 (HIGH)
<!-- audience:high -->
### 고등 포인트
- 구현 의존 표현이 나와도, 대회 기준(16비트 `short`)에서 일관되게 판단합니다.
- 헤더 문항은 왜 틀렸는지 API 이름 수준으로 설명합니다.

### 고등 연계 실습
실습 목표:
- 경계값 2회 갱신 상황을 추적표로 검산합니다.

실습 문제:
```c
#include <stdio.h>

int main(void) {
    short s = 32766;
    s = s + 1;
    s = s + 1;
    printf("%d\n", s);
    return 0;
}
```

체크포인트:
1. 각 단계 저장값을 순서대로 기록했는가?
2. 최종값을 경계값 기준으로 검산했는가?

### 고등 오답 패턴
- 계산 결과만 쓰고, 연산 타입/저장 타입 근거를 생략한다.
- 헤더 오답 선지를 느낌으로 제거하고 API 근거를 남기지 않는다.
