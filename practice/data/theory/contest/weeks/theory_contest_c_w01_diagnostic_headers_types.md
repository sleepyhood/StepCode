### 개념 1) 컴파일러/인터프리터/헤더 기능 판별
- 개념 정의: 용어의 역할과 표준 헤더 기능을 정확히 매칭하는 개념입니다.
- 판별 규칙: 문제 문장을 `번역 도구`, `실행 방식`, `기능 헤더` 중 하나로 먼저 분류한다.
- 판별 규칙: 헤더 문항은 함수/매크로 키워드가 어느 헤더에 속하는지 1:1로 대조한다.
- 추적 절차: 키워드 추출 -> 역할 분류 -> 오답 선지 제거 순으로 풀이한다.
- 오답 포인트: `stdarg.h`를 예외 처리로 오해하거나, 컴파일러와 인터프리터를 같은 개념으로 보면 오답이 발생합니다.

빠른 비교표:

| 항목 | 무엇을 하는가 | 문항에서 자주 나오는 표현 |
| --- | --- | --- |
| 컴파일러 | 소스 코드를 목적 코드/실행 가능한 형태로 번역한다 | 번역, 실행 파일 생성 |
| 인터프리터 | 코드를 읽으며 즉시 실행한다 | 한 줄 실행, 즉시 해석 |
| `stdio.h` | 표준 입출력 함수 선언을 제공한다 | `printf`, `scanf` |
| `time.h` | 시간/날짜 관련 함수 제공 | 시간 계산, 날짜 |
| `assert.h` | 단정 검사용 매크로 제공 | `assert(...)` |
| `stdarg.h` | 가변 인자 처리 도구 제공 | `va_list`, `va_start` |
| `stddef.h` | 공통 타입/매크로 제공 | `size_t`, `ptrdiff_t`, `NULL` |

예시 (변형):
```c
#include <stdarg.h>
#include <stdio.h>

int sum(int n, ...) {
    va_list ap;
    va_start(ap, n);
    int s = 0;
    for (int i = 0; i < n; i++) s += va_arg(ap, int);
    va_end(ap);
    return s;
}

int main(void) {
    printf("%d\n", sum(3, 2, 4, 6));
    return 0;
}
```

### 개념 2) `limits.h`와 `SHRT_MAX` 해석
- 개념 정의: 정수형 범위 상수와 필요한 헤더를 함께 해석하는 개념입니다.
- 판별 규칙: `SHRT_*`는 `short`, `INT_*`는 `int`, `LONG_*`는 `long` 범위를 뜻한다.
- 판별 규칙: 범위 상수를 쓰는 문항은 헤더 포함 여부(`limits.h`)를 먼저 확인한다.
- 추적 절차: 상수 이름 확인 -> 대응 자료형 확인 -> 경계값 의미 해석 순으로 풀이한다.
- 오답 포인트: `SHRT_MAX`를 `INT_MAX`와 혼동하면 선지 제거가 실패합니다.

직관 비유:
- 자료형은 크기가 정해진 저장칸입니다.
- `SHRT_MAX`는 `short` 저장칸에 들어갈 수 있는 최댓값입니다.

형식 규칙:
- 대회/학습 기준에서 `short`는 보통 16비트로 다룬다.
- 대표 범위는 `-32768 ~ 32767`이다.

핵심 상수표:

| 상수 | 의미 | 보통 16비트/32비트 환경 기준 값 |
| --- | --- | --- |
| `SHRT_MIN` | `short` 최솟값 | `-32768` |
| `SHRT_MAX` | `short` 최댓값 | `32767` |
| `INT_MAX` | `int` 최댓값 | `2147483647` |

![limits.h 상수군과 자료형 범위 연결 다이어그램](./data/theory/images/contest_w01_limits_constants_map.svg)

예시 (기본):
```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d\n", SHRT_MAX);
    return 0;
}
```
```io
input:
(없음)
output:
32767
```

예시 (변형):
```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d %d\n", SHRT_MIN, SHRT_MAX);
    return 0;
}
```
```io
input:
(없음)
output:
-32768 32767
```

예시 (함정):
```text
코드에 SHRT_MAX를 쓰면서 limits.h를 포함하지 않으면
컴파일 오류(미정의 식별자)가 발생할 수 있다.
```

### 개념 3) `short` 오버플로우와 정수 승격
- 개념 정의: 연산 시 타입이 승격되고, 대입 시 원래 타입 범위로 돌아오는 과정을 추적하는 개념입니다.
- 판별 규칙: `s + 1` 계산은 먼저 `int`로 승격되어 수행된다.
- 판별 규칙: 계산 결과를 다시 `short`에 저장하면 범위를 넘는 값이 순환되어 저장된다.
- 추적 절차: 초기값 확인 -> 연산 타입 확인 -> 대입 여부 확인 -> 출력식 확인 순으로 검산한다.
- 오답 포인트: "연산 타입"과 "저장 타입"을 같은 것으로 판단하면 출력값을 잘못 고르게 됩니다.

직관 비유:
- 계산할 때는 큰 컵(`int`)으로 옮겨 계산한다.
- 저장할 때는 작은 컵(`short`)으로 다시 붓는다.
- 작은 컵 용량을 넘으면 값이 경계 밖으로 넘어가 순환한다.

판별 프레임:

| 코드 형태 | 계산 타입 | 저장 단계 | 출력 결과 경향 |
| --- | --- | --- | --- |
| `printf("%d", s + 1)` | `int` | 없음 | `32768`처럼 승격 계산값이 보인다 |
| `s = s + 1; printf("%d", s)` | `int` 후 `short` 저장 | 있음 | `-32768`처럼 경계 순환값이 보인다 |

예시 (기본):
```c

    short s = 32766;
    s = s + 2;
    printf("%d\n", s);
    return 0;
}
```


예시 (변형):


## 초등 트랙 (ELEMENTARY)

- 코드 추적은 경계값 1회 갱신까지 안정적으로 처리합니다.

### 초등 연계 실습

실습 문제:
```c
#include <stdio.h>
```

체크포인트:

### 초등 오답 패턴
- 상수 이름은 맞게 고르고 헤더를 틀린다.

## 중등 트랙 (MIDDLE)
<!-- audience:middle -->
### 중등 포인트
- 개념 3에서 연산 타입과 대입 타입을 분리해 설명합니다.
- 헤더 판별 문항은 오답 선지 제거 근거를 1줄로 남깁니다.

### 중등 연계 실습
실습 목표:
- 대입 유무에 따른 출력 차이를 비교합니다.

실습 문제:
```c
#include <stdio.h>

int main(void) {
    short s = 32767;
    printf("%d ", s + 1);
    s = s + 1;
    printf("%d\n", s);
    return 0;
}
```

체크포인트:
1. 첫 출력과 둘째 출력이 다른 이유를 설명했는가?
2. "승격"과 "잘림"을 분리해 적었는가?

### 중등 오답 패턴
- `s+1`을 항상 `short` 계산으로 처리한다.
- 경계값 문항에서 초기값을 누락하고 중간 계산만 적는다.

## 고등 트랙 (HIGH)
<!-- audience:high -->
### 고등 포인트
- 구현 의존 표현이 나와도, 대회 기준(16비트 `short`)에서 일관되게 판단합니다.
- 헤더 문항은 왜 틀렸는지 API 이름 수준으로 설명합니다.

### 고등 연계 실습
실습 목표:
- 경계값 2회 갱신 상황을 추적표로 검산합니다.

실습 문제:
```c
#include <stdio.h>

int main(void) {
    short s = 32766;
    s = s + 1;
    s = s + 1;
    printf("%d\n", s);
    return 0;
}
```

체크포인트:
1. 각 단계 저장값을 순서대로 기록했는가?
2. 최종값을 경계값 기준으로 검산했는가?

### 고등 오답 패턴
- 계산 결과만 쓰고, 연산 타입/저장 타입 근거를 생략한다.
- 헤더 오답 선지를 느낌으로 제거하고 API 근거를 남기지 않는다.
