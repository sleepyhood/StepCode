### 개념 1) 연산/대입/나머지
- 개념 정의: 변수 값이 대입 연산을 거치며 어떻게 변하는지를 추적하는 유형입니다.
- 판별 규칙: `+=`, `-=`, `*=` 같은 누적 대입을 먼저 계산하고, `%`는 파이썬 나머지 규칙으로 판단한다.
- 추적 절차: 초기값 확인 -> 대입 연산 순차 적용 -> 나머지 연산 적용 -> 출력값 후보 비교한다.
- 오답 포인트: 다른 언어 직관으로 음수 나머지를 처리하면 오답이 발생하기 쉽습니다.

음수 나눗셈 전개:
- 파이썬은 아래 관계를 항상 만족하도록 `//`, `%`를 정한다.
- `a = b * (a // b) + (a % b)`
- `b > 0`일 때 나머지 범위는 `0 <= (a % b) < b`다.

예시 전개:
- `-13 // 5 = -3`
- `-13 % 5 = 2`
- 검산: `5 * (-3) + 2 = -13`

![음수 나눗셈/나머지 시각화](./data/theory/images/contest_w01_negative_modulo.svg)

예시 (전개 확인):
```python
print(-13 // 5, -13 % 5)
print(5 * (-13 // 5) + (-13 % 5))
```

```io
output:

-13
```

### 개념 2) 출력 포맷 `.format()`
- 개념 정의: 값 자체가 아니라 "폭(width), 정렬, 자료형" 규칙으로 문자열 결과를 해석하는 유형입니다.
- 판별 규칙: 폭 숫자는 값이 아니라 칸 수이며, 문자열/정수 포맷은 각각의 규칙으로 채워진다.
- 추적 절차: 포맷 문자열을 조각별로 분리 -> 각 조각의 폭/형식 적용 -> 공백 포함 최종 문자열 비교한다.
- 오답 포인트: 폭 숫자를 출력값으로 오해하거나 공백을 무시하면 선택지가 뒤집히기 쉽습니다.

![format 폭(width) 시각화](./data/theory/images/contest_w01_format_width.svg)

| 표기 | 의미 | 기본 정렬 | 폭(Width) 해석 | 예시 코드 | 결과 조각 (`·`=공백) |
| --- | --- | --- | --- | --- | --- |
| `{:d}` | 정수 출력 | 오른쪽 | 최소 칸 수(부족하면 공백 채움) | `"{:6d}".format(314)` | `"···314"` |
| `{:s}` | 문자열 출력 | 왼쪽 | 최소 칸 수(부족하면 공백 채움) | `"{:5s}".format("AB")` | `"AB···"` |
| `{:>6d}` | 정수 출력(오른쪽 강제) | 오른쪽 | 6칸 확보 | `"{:>6d}".format(314)` | `"···314"` |
| `{:<5s}` | 문자열 출력(왼쪽 강제) | 왼쪽 | 5칸 확보 | `"{:<5s}".format("AB")` | `"AB···"` |
| `{:^6s}` | 문자열 가운데 정렬 | 가운데 | 6칸 확보 | `"{:^6s}".format("AB")` | `"··AB··"` |
| `{:2d}` + 큰 값 | 폭보다 값이 길면 그대로 출력 | 해당 없음 | 잘리지 않음 | `"{:2d}".format(123)` | `"123"` |

예시 (기본):
```python
print("B{:6d}X{:5s}B".format(314, "AB"))
```
```io
input:
(없음)
output:
B   314XAB   B
```

예시 (변형):
```python

```
```io
input:
(없음)
output:

```

예시 (함정):


### 개념 3) 함수 키워드/스코프
- 개념 정의: 함수 선언 키워드와 전역 변수 대입 시 필요한 키워드를 구분하는 유형입니다.
- 판별 규칙: 함수 선언은 `def`, 함수 내부 전역 대입은 `global`을 사용한다.
- 추적 절차: 함수 밖/안 변수 위치 확인 -> 함수 내부에서 "읽기"인지 "대입"인지 구분 -> 키워드 필요 여부 판단한다.
- 오답 포인트: 전역 변수 조회와 전역 변수 대입을 같은 규칙으로 보면 오류가 발생합니다.

| 키워드 | 언제 필요 | 필요 없는 경우 | 변수 영향 범위 | 메모 |
| --- | --- | --- | --- | --- |
| `def` | 함수 정의를 시작할 때 | 일반 코드 블록/조건문 내부 | 함수 이름을 전역/현재 스코프에 바인딩 | 선언 키워드 |
| `global x` | 함수 내부에서 전역 변수 `x`에 대입/증감할 때 | 전역 변수 읽기만 할 때 | 함수 밖 `x` 값이 변경됨 | 쓰기(대입) 시 핵심 |
| `global` 없음 | 함수 내부 지역 변수만 다룰 때 | 전역 값을 바꿔야 할 때 | 함수 내부 지역 변수만 변경 | 같은 이름이면 가림(shadowing) |

예시 (기본):
```python
total = 1

def add_one():
    global total
    total += 1

add_one()
print(total)
```
```io
input:
(없음)
output:
2
```

예시 (변형):
```python

def show():
    print(count)

show()
```
```io
input:
(없음)
output:
5
```

예시 (함정):
```python
score = 10

def change():
    score = score + 1

change()
```
```io
input:
(없음)
output:
UnboundLocalError
```

### 개념 4) 반올림 `round`
- 개념 정의: 자리수 인자 `n`의 의미를 해석해 반올림 결과를 판단하는 유형입니다.
- 판별 규칙: `n>0`은 소수부, `n=0`은 정수, `n<0`은 정수부 앞자리 반올림이다.
- 추적 절차: 목표 자리 확인 -> 해당 자리 다음 숫자 확인 -> 반올림 적용 후 형식 비교한다.
- 오답 포인트: `round(x)`와 `round(x, 1)`, `round(x, -1)`을 섞어 판단하면 실수가 잦습니다.

| 표현 | 의미 | 기준 자리 | 예시 (`x=54.378`) | 결과 |
| --- | --- | --- | --- | --- |
| `round(x, 2)` | 소수 둘째 자리까지 | 소수점 아래 2번째 | `round(54.378, 2)` | `54.38` |
| `round(x, 1)` | 소수 첫째 자리까지 | 소수점 아래 1번째 | `round(54.378, 1)` | `54.4` |
| `round(x)` / `round(x, 0)` | 정수 자리 반올림 | 일의 자리 | `round(54.378)` | `54` |
| `round(x, -1)` | 십의 자리 반올림 | 십의 자리 | `round(54.378, -1)` | `50.0` |
| `round(x, -2)` | 백의 자리 반올림 | 백의 자리 | `round(54.378, -2)` | `100.0` |

예시 (기본):
```python
x = 54.378
print(round(x, 1))
```
```io
input:
(없음)
output:
54.4
```

예시 (변형):
```python

```
```io

(없음)

```

예시 (함정):

### 개념 5) 조건식 truthy/falsy 판별
- 개념 정의: 값의 자료형/상태에 따라 조건문에서 참/거짓이 되는 규칙을 해석하는 유형입니다.
- 판별 규칙: `False`, `0`, `0.0`, `''`, `[]`, `{}`, `None`은 거짓이고, 그 외 대부분은 참이다.
- 추적 절차: 각 조건식 값을 자료형으로 분류 -> truthy/falsy 적용 -> 누적 문자열/카운트 변화를 기록한다.
- 오답 포인트: 문자열 내용이 `"False"`여도 비어 있지 않으면 참이라는 점을 자주 놓칩니다.

| 값 | 분류 | `if 값:` 평가 | 이유 |
| --- | --- | --- | --- |
| `0`, `0.0` | 숫자 0 | 거짓 | 0은 falsy |
| `''` | 빈 문자열 | 거짓 | 길이 0 |
| `[]`, `{}` | 빈 컨테이너 | 거짓 | 원소 0개 |
| `None` | 없음(null) | 거짓 | 파이썬 기본 falsy |
| `"0"`, `"False"` | 비어있지 않은 문자열 | 참 | 내용과 무관, 길이 > 0 |
| `[0]`, `-1`, `3.14` | 비어있지 않음/0 아님 | 참 | 값이 존재 |

예시 (기본):
```python
msg = ""
if "0":
    msg += "A"
if []:
    msg += "B"
if -2:
    msg += "C"
print(msg)
```
```io
input:
(없음)
output:
AC
```

예시 (변형):
```python
cnt = 0
for v in [0, "", "OK", None, 7]:
    if v:
        cnt += 1
print(cnt)
```
```io
input:
(없음)
output:
2
```

예시 (함정):
```python
if "False":
    print("T")
else:
    print("F")
```
```io
input:
(없음)
output:
T
```

## 초등 트랙 (ELEMENTARY)
<!-- audience:elementary -->
### 초등 포인트
- 긴 설명보다 "한 줄 추적"을 먼저 적용하는 방식이 효과적입니다.
- 함수 키워드와 조건식 참/거짓 규칙을 우선 고정하는 것이 중요합니다.

### 초등 이론 보강
- 연산은 순서대로 값만 바꿔 기록합니다.
- 포맷은 칸 수를 먼저 세고 값을 넣습니다.
- 조건식은 "비어 있는가"를 먼저 확인합니다.

초등 규칙 카드:
1. `%`는 파이썬 규칙으로 판단한다.
2. 포맷 숫자는 칸 수다.
3. 함수 선언은 `def`다.
4. `global`은 전역 대입에서 쓴다.
5. 빈 컨테이너와 0은 거짓이다.

### 초등 연계 연습
1. `b = -8; b %= 3`에서 결과 부호는 어떤 기준으로 정하나요?
2. `print("|{:4s}|".format("A"))`에서 공백은 어디에 붙나요?
3. `if "":`는 참인가 거짓인가요?

### 초등 오답 패턴
- 나머지 연산에서 음수 규칙을 반대로 적용합니다.
- 공백을 출력 문자열 일부로 보지 않습니다.
- 비어 있지 않은 문자열을 거짓으로 착각합니다.

## 중등 트랙 (MIDDLE)
<!-- audience:middle -->
### 중등 포인트
- "문법 이름 문제"와 "코드 추적 문제"를 같은 규칙으로 연결하는 훈련이 필요합니다.
- 반올림 자리수와 포맷 폭을 동시에 다루는 복합 문항 대비가 중요합니다.

### 중등 이론 보강
- 연산/포맷/조건식을 각각 분리한 뒤 합치는 습관이 정확도를 높입니다.
- 전역 대입과 지역 대입을 식별하는 습관이 필요합니다.

중등 판별 루틴:
1. 연산자 우선순위와 대입 순서를 분리한다.
2. 포맷 문자열을 조각 단위로 해체한다.
3. 조건식은 truthy/falsy로만 판정한다.
4. 함수 변수는 대입 여부로 스코프를 판단한다.

### 중등 연계 연습
1. 아래 코드에서 전역 선언이 필요한 줄을 고르시오.
```python
k = 3

def f():
    # 어떤 줄에서 global 필요?
    pass
```
2. `round(83.249, 1)`, `round(83.249, 2)`, `round(83.249, -1)`의 역할 차이를 설명하시오.
3. `if {}, if "N", if 0.0`의 참/거짓을 분류하시오.

### 중등 오답 패턴
- `round` 자리수 인자를 소수점 자리와 반대로 해석합니다.
- 지역 변수 대입을 전역 변수 변경으로 오해합니다.

## 고등 트랙 (HIGH)
<!-- audience:high -->
### 고등 포인트
- 보기형 문항은 "틀린 판단 1개 제거" 전략으로 접근하는 것이 효율적입니다.
- 직접 계산보다 판별 규칙 적용 순서를 먼저 세우는 훈련이 필요합니다.

### 고등 이론 보강
- 본 주차는 연산/포맷/스코프/조건식의 경계선 구분이 핵심입니다.
- 동일한 코드라도 입력값/초기값이 바뀌면 판단 결과가 달라지는 이유를 설명할 수 있어야 합니다.

고등 판별 프레임:
1. 개념 축(연산/포맷/스코프/조건식)을 먼저 분류한다.
2. 각 축의 규칙을 적용해 후보를 줄인다.
3. 남은 후보만 계산으로 검증한다.

### 고등 연계 연습
1. 조건식, 포맷, 반올림이 섞인 짧은 코드에서 오답 유도 지점을 2개 찾으시오.
2. 같은 코드에서 초기값만 바꿨을 때 결과가 뒤집히는 사례를 작성하시오.
3. "정답 자체"가 아니라 "판별 근거" 3가지를 쓰시오.

### 고등 오답 패턴
- 계산은 맞지만 판별 근거를 설명하지 못합니다.
- 코드 한 줄만 보고 전체 흐름을 생략합니다.

## {view:teacher} 평가
- 항목: 진단 리포트 작성 (개념 정확도 + 추적 정확도)
