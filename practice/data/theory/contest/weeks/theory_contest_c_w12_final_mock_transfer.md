### 개념 1) 복합 조건 분해
- 개념 정의: 반복문 안에 조건문이 여러 개 있을 때, 어떤 조건이 상태를 바꾸는지 분리해 읽는 방법입니다.
- 핵심 내용:
  - 복합 조건은 역할별로 나누면 해석이 쉬워집니다.
  - 한 회차에서 실제로 바뀌는 변수만 추적하면 계산 실수를 줄일 수 있습니다.
  - `if -> else if -> else`는 위에서 아래 순서로 한 경로만 실행됩니다.
- 판별 규칙:
  - 복합 조건은 `분기 분류 -> 갱신 변수 표시 -> 원래 실행 순서 유지`로 해석한다.
- 오답 포인트: `if`와 `else`의 갱신 대상을 혼동하면 같은 입력에서도 누적값이 달라집니다.

| 분기 유형 | 대표 형태 | 상태 변화 |
| --- | --- | --- |
| 누적 갱신 | `if (cond) x += v` | `x`만 갱신 |
| 건너뛰기 | `if (cond) continue` | 이후 코드 미실행 |
| 종료 | `if (cond) break/return` | 반복/함수 즉시 종료 |
| 대체 분기 | `if ... else ...` | 한 회차에 한 경로만 실행 |

![복합 분기 조건을 분해해 누적 변수를 추적하는 흐름도](./data/theory/images/contest_w12_complex_branch_flow.svg)

예시 (기본):
```c
#include <stdio.h>

int main(void) {
    int v = 0;
    for (int i = 1; i <= 6; i++) {
        if (i % 2 == 0) v += i;
        else v -= 1;
    }
    printf("%d\n", v);
    return 0;
}
```
```io

(없음)
output:
6
```



### 개념 2) 추적표 기반 검산
- 개념 정의: 실행 흐름을 표로 기록해 계산 과정과 출력값을 일치시키는 검산 방법입니다.
- 핵심 내용:
  - 추적표는 계산 과정을 눈에 보이게 만들어 경계 실수를 줄입니다.
  - 열을 적게 유지하면 핵심 변수 변화만 빠르게 확인할 수 있습니다.
  - 출력 직전 값을 따로 표시하면 최종 대입 오류를 막을 수 있습니다.
- 판별 규칙:
  - 추적표 검산은 `초기 행 -> 변화 행 -> 출력 직전 행` 3단계로 고정한다.
- 오답 포인트: 머릿속 계산으로 중간 행을 생략하면 반복 횟수와 경계값에서 누락이 발생합니다.

| 열 이름 | 기록 내용 | 실수 방지 포인트 |
| --- | --- | --- |
| 단계 | `i` 값/반복 회차 | 누락 회차 여부 확인 |
| 조건 결과 | 참/거짓 + 판정식 | 분기 경로 착오 방지 |
| 핵심 변수 | 갱신된 변수의 새 값 | 이전 값과 구분 기록 |
| 출력 직전 | 출력식 대입 결과 | 최종 검산용 별도 행 |

![추적표 열 구성과 출력 직전 검산 순서를 보여주는 도식](./data/theory/images/contest_w12_trace_table_check.svg)

예시 (기본):
```c
#include <stdio.h>

int main(void) {
    int t = 0;
    for (int i = 0; i < 4; i++) t += i * 2;
    printf("%d\n", t);
    return 0;
}
```


```c
        int n = a + b;
```

### 개념 3) 시간 안배와 선택 전략
- 개념 정의: 제한 시간에서 풀이 순서를 조정해 확정 점수를 먼저 확보하는 운영 전략입니다.
- 핵심 내용:
  - 실전에서는 정답률이 높은 문항을 먼저 확정하는 것이 유리합니다.
  - 문항 상태를 분류하면 시간 사용이 흔들리지 않습니다.
  - 보류 문항은 마지막에 경계값 중심으로 재검토해야 효율이 좋습니다.
- 판별 규칙:
  - 시간 운영은 `즉시 풀이 -> 검산 후 제출 -> 보류 재진입` 순서로 관리한다.
- 오답 포인트: 어려운 문항 한 개에 시간을 고정하면 쉬운 문항 확정 기회를 놓치게 됩니다.

| 문항 상태 | 판단 기준 | 권장 행동 |
| --- | --- | --- |
| 즉시 풀이 | 추적표 6행 이내/규칙 명확 | 바로 풀이 후 제출 |
| 검산 후 제출 | 경계값/분기 다수 | 1회 풀이 + 1회 검산 |
| 보류 | 핵심 규칙 미확정 | 체크표시 후 다음 문항 이동 |
| 재진입 | 남은 시간 20% 이상 | 경계 입력부터 재검토 |

![시험 시간 내 문항 선택과 보류 전략 보드를 나타내는 도식](./data/theory/images/contest_w12_time_strategy_board.svg)

예시 (기본):
```text
총 20분, 5문항
- 1차 10분: 추적표 6행 이내 문항 3개 우선 해결
- 2차 7분: 이분 탐색/경계 검증 문항 1개 해결
- 3차 3분: 제출값 재확인 및 단위/부호 검산
```

예시 (변형):
```text
총 25분, 6문항
- 1차 12분: 조건 분해형 4문항 처리
- 2차 8분: 탐색형 1문항 처리
- 3차 5분: 보류 1문항 핵심 분기만 확인
```

예시 (함정):
```text
오답 패턴
- 시작부터 최난도 1문항에 12분 사용
- 중간 난도 2문항 미시도
- 마지막 3분에 추측 제출
```

### 초등 연계 실습
실습 목표:

실습 문제:
```c
#include <stdio.h>

int main(void) {
    int n = 7;
    int s = 0;
    for (int i = 1; i <= n; i++) {

    return 0;
}
```

체크포인트:
1. `i` 값별 조건 통과/미통과를 구분했는가?

## 중등 트랙 (MIDDLE)
<!-- audience:middle -->
### 중등 포인트
- 누적 조건과 경계 조건을 같은 표에서 함께 검산하는 습관이 필요합니다.

### 중등 연계 실습
실습 목표:
- 경계값을 포함한 분기 흐름을 표로 추적합니다.

실습 문제:
```c
#include <stdio.h>

int main(void) {
    int a[6] = {5, 7, 2, 9, 4, 8};
    int c = 0, cnt = 0;
    for (int i = 0; i < 6; i++) {
        if (a[i] <= 6) cnt++;
        else c += a[i];
    }
    printf("%d %d\n", cnt, c);
    return 0;
}
```

체크포인트:
1. 경계값(`<= 6`) 처리 문항을 별도 표시했는가?
2. 분기별로 어떤 변수가 갱신되는지 분리해 적었는가?

## 고등 트랙 (HIGH)
<!-- audience:high -->
### 고등 포인트
- 탐색형 문항에서 `가능/불가능 판정`과 `탐색 구간 이동`을 분리해야 합니다.

### 고등 연계 실습
실습 목표:
- 판정 함수 관점으로 탐색 구간 이동 근거를 정리합니다.

실습 문제:
```c
#include <stdio.h>

int main(void) {
    int a[5] = {6, 8, 5, 7, 4};
    int l = 0, r = 30, ans = -1;

    while (l <= r) {
        int mid = (l + r) / 2;
        int cnt = 1, sum = 0;
        for (int i = 0; i < 5; i++) {
            if (sum + a[i] <= mid) sum += a[i];
            else {
                cnt++;
                sum = a[i];
            }
        }

        if (cnt <= 3) {
            ans = mid;
            r = mid - 1;
        } else {
            l = mid + 1;
        }
    }

    printf("%d\n", ans);
    return 0;
}
```

체크포인트:
1. `cnt <= 3` 판정이 참일 때 구간을 왜 왼쪽으로 이동하는지 설명했는가?
2. `l`, `r`, `mid`, `ans` 변화를 최소 3회 이상 기록했는가?
