# 경시 이론 문서 작성 규칙 (Contest Theory Rules)

## 1) 목적
- 이 문서는 주차별 이론 문서를 작성할 때의 공통 규칙입니다.
- 목표는 "현재 문제 정답 맞히기"가 아니라 "유형 전이(응용) 가능성"을 만드는 것입니다.

## 2) 현재 문제점
- 이론이 특정 문제 정답으로 바로 연결되는 문장 위주로 작성되는 경향이 있습니다.
- 예시가 실제 문제와 거의 동일해서 학생이 응용하기 어렵습니다.
- 결과적으로 암기형 풀이가 되고, 변형 문항 대응력이 떨어집니다.

## 3) 핵심 원칙
1. 이론은 문제보다 넓어야 한다.
- 한 문제에만 통하는 규칙이 아니라, 같은 유형 전체에 적용 가능한 규칙을 설명한다.

2. 예시는 유사 예시를 사용한다.
- 실제 문제 코드/숫자/문구를 그대로 재사용하지 않는다.
- 같은 개념의 유사 패턴으로 예시를 만든다.

3. 해설은 정답 유출형이 아니어야 한다.
- 최종 출력만 쓰지 않는다.
- 개념 정의, 핵심 내용, 오답 포인트를 먼저 제시한다.

4. 문제-이론 연결은 하되, 문제 복제는 하지 않는다.
- 어떤 개념이 연결되는지만 표기하고, 문제 본문 재현은 금지한다.

5. 주차 분리를 지킨다.
- 주제가 겹치더라도 해당 주차 수준에서 필요한 내용만 설명한다.

6. 직관 비유와 형식 규칙을 함께 제시한다.
- 학생이 많이 헷갈리는 개념은 비유와 식/범위를 함께 제시한다.
- 설명 흐름은 `개념 -> 비유 -> 규칙 -> 예시` 순서를 권장한다.

7. 중학생 난도를 기본으로 한다.
- 어려운 용어를 쓰더라도 바로 뒤에 쉬운 말로 풀어쓴다.
- 한 문장에 조건을 많이 넣지 않고, 짧은 문장으로 나눈다.
- 무엇을 해야 하는지보다 무엇인지를 먼저 설명한다.

8. 개념 개수 가드레일을 지킨다.
- 주차당 권장 개념 수는 4~6개다.
- 최소 3개, 최대 7개를 기본 범위로 한다.
- 진단/총정리 등 특수 주차는 예외를 허용하되, 문서에 근거를 1줄 기록한다.

## 4) 예시 작성 규칙
1. 금지
- 실제 기출의 숫자/문자열/선지를 그대로 사용
- 실제 문제 코드와 동일한 코드 블록 사용
- 정답 직접 유도 문장(예: 그래서 정답은 ...)

2. 권장
- 구조는 같고 값은 다른 유사 예시 사용
- 예시 라벨은 `예시 (기본)`, `예시 (변형)`, `예시 (함정)`
- 각 예시는 결과 확인이 가능하도록 출력값 포함

3. 예시 최소 구성
- 기본 예시 1개
- 변형 예시 1개
- 함정 예시 1개

4. 연계 실습 블록 규칙
- 트랙별 연계 실습은 코드 중심으로 작성한다.
- 섹션 구성은 `실습 목표 -> 실습 문제 -> 체크포인트`를 기본으로 한다.
- 연계 실습에는 정답 노출형 입출력 블록을 넣지 않는다.

## 5) 설명 구조 규칙
모든 핵심 개념은 아래 구조를 기본으로 작성한다.
1. 개념 정의: 이 개념이 무엇인지 설명한다.
2. 핵심 내용: `핵심 내용:`을 한 번만 쓰고 하위 목록으로 정리한다.
3. 오답 포인트: 어디서 틀리기 쉬운지 설명한다.
4. (선택) 판별 규칙: 문제 판별에 꼭 필요할 때만 넣는다.
5. (선택) 추적 절차: 계산 순서가 핵심일 때만 넣는다.
6. 유사 예시: 기본/변형/함정 예시를 둔다.

추가 규칙:
- 난점 개념은 아래 3요소를 함께 둔다.
1. 직관 모델(비유)
2. 형식 규칙(식/범위)
3. 검산 예시(대입 확인)

## 6) 어체 규칙
1. 기본 어체
- 설명/안내/정의 문장은 `~입니다.`로 끝낸다.

2. 예외 어체
- 규칙/루틴/체크리스트/판별 프레임은 `~다.`로 끝낸다.
- `## 학습 목표` 불릿은 명사형/동사원형 개조식으로 작성할 수 있으며 `~입니다.` 종결을 강제하지 않는다.

3. 금지 어체
- 같은 섹션 안에서 `~다.`와 `~입니다.`를 무작위로 섞지 않는다.
- 같은 역할의 라벨(예: `핵심 내용:`)을 한 개념 안에서 반복하지 않는다.

## 7) 문제/정답 문서와의 관계
1. theory 문서
- 개념, 규칙, 실수 패턴 중심

2. problem 문서
- 실제 문항 원문 중심

3. answer 문서
- 정답 + 해설 메모 중심
- 해설 메모도 정답 직접 유도 문장을 최소화한다.

## 7-1) 노출 정책 (학생/교사)
1. `## 메타` 섹션
- 문서 관리용 정보(week/slug/audience)는 메타 섹션에 둔다.
- 메타는 교사용 정보로 취급하며 학생용 화면에서는 노출하지 않는다.

2. `## 공통 미니 체크`
- 학생이 직접 작성하는 제출형 블록으로 작성한다.
- 권장 형식: `문항:` + `답안 작성:` (정답/근거 분리)
- 정답 공개형 해설은 이 섹션에 넣지 않는다.

## 7-2) 섹션 사용 규칙 (현재 표준)
1. `## 학습 목표`
- 해당 주차에서 배우는 내용만 작성한다.
- 문제 파일명/운영 가이드 문구는 넣지 않는다.
- 개조식(불릿)으로 작성한다.
- 권장 개수는 3~5개다.
- 각 항목은 짧은 개조식으로 작성하며 명사형/동사원형을 권장한다.
- `~하는 것이 목표입니다.` 반복 종결은 사용하지 않는다.
- 문장 길이는 짧게 유지하고(권장 20~35자 내외), 중학생이 바로 이해할 수 있는 단어를 쓴다.

2. `## 문항-개념 빠른 연결`
- 현재 C 이론 표준에서는 사용하지 않는다.

3. `## 세분 개념 번호`
- 현재 C 이론 표준에서는 별도 섹션으로 두지 않는다.
- 세분 개념이 필요하면 실제 `### 개념 n)` 헤더로 직접 드러낸다.

## 8) 품질 체크리스트 (작성 후 필수)
1. 이론 예시가 실제 문제와 동일하지 않은가
2. 개념이 최소 2개 이상의 변형 문항에 적용 가능한가
3. 정답 번호/값을 직접 노출하는 설명이 과도하지 않은가
4. 오답 포인트가 명시되어 있는가
5. 어체가 규칙에 맞게 통일되었는가
6. 다른 주차와 주제 중복이 없는가
7. 메타/교사용 정보가 학생용 본문에 섞이지 않았는가
8. 연계 실습에 정답 노출형 입출력 블록이 들어가지 않았는가
9. 학습 목표가 주차 학습 내용 중심으로만 작성되었는가
10. 학습 목표가 개조식(불릿) 3~5개로 작성되었는가
11. `핵심 내용:`이 한 개념당 한 번만 쓰였는가
12. 설명 문장이 중학생 수준에서 읽히는 난도인가
13. 개념 개수가 가드레일(권장 4~6, 범위 3~7)을 벗어나지 않는가

## 9) 권장 템플릿

## 10) 운영 규칙
- 기존 이론 문서를 고칠 때도 이 규칙을 우선 적용한다.
- 기출 원문이 바뀌어도 theory는 개념 중심을 유지한다.
- 문제 교체 시 theory는 예시 숫자/맥락만 조정하고 구조는 유지한다.
- 각 주차 이론은 해당 주차 problem/answer를 풀 수 있는 최소 개념을 반드시 포함한다.
- 개념 누락 점검 시, 문항별로 `필요 개념 -> 이론 섹션` 역매핑이 가능해야 한다.

## 11) SVG 작성 규칙
1. 목적 규칙
- SVG 1개는 개념 1개만 설명한다.

2. 제목 규칙
- 이미지 내부 좌상단 헤더(큰 제목)는 넣지 않는다.
- 문서 제목/섹션 제목과 중복되는 제목 텍스트를 넣지 않는다.

3. 언어 규칙
- 설명 문구는 한국어로 통일한다.
- 코드/수식/함수명은 원문 표기를 허용한다.

4. 폰트 규칙
- 기본 폰트 스택은 아래로 고정한다.
- `"Pretendard", "Noto Sans KR", "Malgun Gothic", "Apple SD Gothic Neo", sans-serif`

5. 크기 규칙
- 기본 캔버스는 가로형을 사용한다.
- 일반 다이어그램은 `980x320`, 흐름/격자형은 `980x360`을 기본으로 한다.

6. 색상 규칙
- 의미별 색을 고정해 재사용한다.
- 기본 텍스트/선, 강조(파랑), 경고/제외(빨강), 배경 박스(연회색) 체계를 유지한다.

7. 표기 규칙
- 출력 공백을 설명할 때는 `_`로 표기한다.
- 기호/색 의미가 있는 경우 범례를 함께 제공한다.

8. 난이도 규칙
- SVG는 특정 문항 정답을 직접 노출하지 않는다.
- 문제 직접 복제 대신 범용 예시 구조를 사용한다.

9. 접근성 규칙
- 문서 삽입 시 alt 텍스트를 반드시 작성한다.
- alt 텍스트는 무엇을 보여주는 그림인지 한 줄로 명시한다.

10. 파일명 규칙
- 파일명은 `contest_wNN_topic_key.svg` 패턴으로 작성한다.
- 소문자/언더스코어 기반으로 통일한다.

11. 배치 규칙
- 각 개념 설명 직후, 첫 코드 예시 전에 SVG를 배치한다.
- 같은 개념 안에서 SVG를 여러 개 쓸 경우 핵심 그림 1개를 먼저 배치한다.

12. 검수 규칙
- 삽입 전 아래 3가지를 점검한다.
- 한글 깨짐이 없는가.
- 모바일 폭에서 텍스트/도형 겹침이 없는가.
- 문서 링크 경로가 정상 동작하는가.
