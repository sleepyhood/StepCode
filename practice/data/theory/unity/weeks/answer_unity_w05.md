# Unity 주차 정답지 W05

## 메타
- 대상 문제지: `problem_unity_w05.md`
- 유닛: U05 Transform/Lifecycle

## 정답표
| 문항 ID | 정답 | 한 줄 근거 |
|---|---|---|
| P01 | B | `turretMount` 속성에 정상적으로 닿기 위해서는 부모 배열의 각 요소 타입 자체가 바로 속성을 감싸고 소유한 `Mount` 클래스 형태여야 함 |
| P02 | C | 반환할 목록의 원본인 메모리에 할당된 `result` 객체가 배열 기호 `[]`를 포함한 여러 `Transform` 객체들의 컬렉션 배열이므로, 메서드 반환 자료형도 `Transform[]`이어야 함 |

## 해설
### P01
- 개념 정의: 중첩 클래스(Nested Class, `Mount`)를 선언하고, 인스펙터에 여러 개를 노출시키기 위해서는 해당 클래스를 데이터 타입 범주로 사용하는 명시적인 제네릭 리스트나 배열(`[]`) 변수를 선언해야만 합니다.
- 오답 포인트: 배열 내부에 들어있는 가장 안쪽 필드가 `Transform turretMount` 형식이라는 이유만으로, 껍데기 배열 선언 타입도 덩달아 최종 멤버인 `Transform`의 베열이어야 할 것으로 지레 짐작합니다.
- 판별 기준: `tMounts[0].turretMount` 코드가 작동하려면 배열 원소 `tMounts[0]` 안에 `.turretMount`가 포함되어 있어야 하므로, `tuureMount`를 멤버로 가지는 타입 공간, 즉 바로 `Mount` 껍데기 자체가 배열의 선언 주체임을 인지해야 합니다.

### P02
- 개념 정의: C#의 문법적 메서드는 언제나 자신이 선언한 타입 지정자(자료형) 시그니처와, 실제로 마지막에 바깥으로 `return` 뱉어내는 내부 변수의 물리적인 메모리 데이터 타입이 형태가 똑같아야만 컴파일 과정이 승인됩니다.
- 오답 포인트: 반환되는 `result`가 `Transform` 객체를 다루기 때문에 단순히 배열 기호를 생략해 버리고 원시 타입인 스칼라 객체 구조의 `Transform` 하나를 선택하는 경우가 잦습니다.
- 판별 기준: `new Transform[childCount]`로 생성된 것은 `Transform`의 무리(집합 배열)이고 실제 `result`의 선언부 역시 `Transform[]`이므로, 바깥으로 던지는 함수의 시그니처도 `Transform` 뒤에 `[]`를 붙여 복수 개를 의미시켜야 오류가 없습니다.

### P03
- 개념 정의: 유니티의 객체 생명주기(Lifecycle) 규칙 상 데이터가 담긴 컴포넌트를 미리 캐싱하여 만반의 준비를 갖추는 단계는 가급적 다른 오브젝트의 동작과 꼬이지 않을 가장 첫 시점인 `Awake`가 가장 적절하며, 게임 중 수시로 오브젝트가 껐다 켜질 때마다 매번 특정 포즈 전환이나 스크립트 장착을 반응해야 하는 것은 이벤트 콜백인 `OnEnable`입니다.
- 오답 포인트: 이런 컴포넌트를 언제, 어떤 타이밍에 엔진이 자동 호출해 주는지 순서를 몰라 모든 장착 로직을 조건문 없이 통째로 쏟아 넣거나, 심지어 `Awake` 블록 이전에 `OnEnable`이 먼저 불릴 수 있다고 잘못 판단하여 역순으로 조립합니다.
- 판별 기준: 제시받은 스크립트 블록들을 조립할 때 최우선적으로 클래스 베이스 선언부와 단 1회성 로딩 `Awake` 덩어리(블록 B, C)를 위에 배치하고, 연달아 불릴 껐다 켜기 전용 `OnEnable` 몸통(블록 A, D)을 후행으로 이어서 닫아주는 문법적 완성 유무를 살핍니다.

### X01
- 개념 정의: 엔진 내에서 특정 UI 부모(`root`)가 품은 수많은 요소나 3D 계층 하위 오브젝트의 모든 구성원을 스크립트로 파악하려면, 반드시 현재 품고 있는 갯수(`childCount`)와 해당 자식을 차례차례 꺼내오는 인덱스 API(`GetChild`)를 세트로 활용해 내부 인벤토리를 만듭니다.
- 오답 포인트: 자식의 수를 알아오는 `root.childCount`를 깜빡하고 배열 인스턴스 길이를 임의 상수나 무한 루프로 돌리다가 Array Bounds 초과 예외의 인덱스 오류 프로그램 다운을 맞습니다.
- 판별 기준: 빈 배열 크기를 명확히 `childCount`로 정의하고, `0`부터 `childCount-1`까지를 한계로 하는 표준적인 `for` 순회 제어문 안쪽에, 자식 레퍼런스를 배열의 각 방(`result[i]`)에 정상적으로 세팅하고 저장했는지 채점합니다.

### X02
- 개념 정의: 한 번 로딩하면 그만인 `GetComponent` 성능 부하를 가진 초기화 작업을 상태 변화 시마다 마구잡이로 작동하게 만들면 게임 렉이나 성능 하락의 주원인이 됩니다. 이 둘(로딩 vs 스위치 토글)의 책임을 나누어 배치하는 구조화가 유니티 설계의 핵심 중 하나입니다.
- 오답 포인트: `Start`나 `Update` 메서드같이 가장 대중적인 메서드만 익숙하여, 모든 프레임마다 장착 여부 로직을 반복 검사하고 참조를 계속 다시 찾는(Polling) 나쁜 습관성 오개념을 가지게 됩니다.
- 판별 기준: 무거운 준비(초기화) 데이터 작업 요소는 무조건 1회 실행인 `Awake`(또는 경우에 따라 `Start`)로 미뤄 캐싱해 두고, 상태를 조작하고 무기를 화면에 붙이는 장착 명령만 껐다 켜기 전용 분기인 `OnEnable`에게 집중시킨 (B) 구조의 책임 분리 설계를 정확히 지목해야 합니다.
