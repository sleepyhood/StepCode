# Unity 주차 정답지 W05

## 메타
- 대상 문제지: `problem_unity_w05.md`
- 유닛: U05 Transform/Lifecycle

## 정답표
| 문항 ID | 정답 | 한 줄 근거 |
|---|---|---|
| P01 | B | `tMounts` 배열에 담긴 원소들이 `.turretMount` 속성을 가지려면 해당 요소 타입 자체가 `Mount` 클래스여야 함 |
| P02 | C | 반환할 `result` 변수가 `Transform[]` 타입으로 생성되어 뱉어지므로, 메서드 반환 타입도 `Transform[]`이어야 함 |
| P03 | B | 최초 실행 시점인 `Awake`(B, C)에서 캐싱을 먼저 하고, 활성화 시점인 `OnEnable`(A, D)에 부착 처리를 하는 B가 올바른 순서 |
| X01 | A | `childCount`로 빈 배열 크기를 생성하고, `GetChild(i)`로 순회 인덱스의 자식을 매칭하여 담은 C# 로직 구성인 A가 정답 |
| X02 | B | 무거운 데이터 로드는 `Awake`에서 1회 캐싱하고, 반복 부착 트리거는 `OnEnable`이 짊어지는 역할 분배가 베스트 프랙티스 |

## 해설
### P01
- 개념 정의: 중첩 클래스(Nested Class, `Mount`)를 선언하고, 인스펙터에 여러 개를 노출시키기 위해서는 해당 클래스를 데이터 타입 범주로 사용하는 배열(`[]`) 변수를 선언해야 합니다.
- 오답 포인트: 배열 내부 멤버 필드가 `Transform turretMount` 형식이라는 이유로 배열 자체 선언부도 `Transform` 타입이어야 한다고 헷갈리기 쉽습니다.
- 판별 기준: `tMounts[0].turretMount` 코드가 작동하려면 `tMounts[0]`이 `.turretMount` 속성을 포함한 `Mount` 객체여야 하므로, B가 정답입니다.

### P02
- 개념 정의: C#의 메서드는 선언된 반환 타입 시그니처와 실제 `return`하는 변수의 물리적 메모리 데이터 타입이 일치해야 합니다.
- 오답 포인트: 반환되는 `result`가 복수형 배열임에도 단순히 `Transform` 단수를 고르는 실수를 피해야 합니다.
- 판별 기준: `result`가 `Transform[]`이므로, 반환형 역시 대괄호가 붙은 `Transform[]` (C)가 정답입니다.

### P03
- 개념 정의: 유니티 생명주기상 객체 로드 시 1회성 캐싱(`Awake`)이 활성화 이벤트성 반응(`OnEnable`)보다 무조건 선행되어야 함이 정석입니다.
- 오답 포인트: 스크립트 블록의 선언부가 포함된 B를 가장 먼저 두고, `Awake` 중괄호가 닫히는 C를 연달아 둔 뒤, `OnEnable` 시작 블록인 A와 내부 코드가 마무리되는 D를 후행 배치해야 함을 순서대로 추론해야 합니다.
- 판별 기준: B ➔ C ➔ A ➔ D 순서로 완성도 있게 배치된 B가 정답입니다.

### X01
- 개념 정의: `root.childCount`로 자식의 전체 개수를 확인하여 배열의 크기를 할당하고, `root.GetChild(index)`를 활용해 인덱스 번호에 해당하는 직계 자식 Transform을 가져와 배열에 담아 리턴합니다.
- 오답 포인트: `GetChild(i)`에 매개변수를 빼먹어 컴파일 에러를 내거나(`GetChild`), 단순 수치(`childCount`)를 배열에 대입하거나, 배열 타입 형변환 오류를 유발하는 함정을 걸러냅니다.
- 판별 기준: 올바른 배열 할당 및 API 형태를 완벽히 준수한 A가 정답입니다.

### X02
- 개념 정의: 매번 `GetComponent`를 수행해 무거운 캐싱 참조를 돌리는 것을 피하고, 1회성 로딩 `Awake`와 상태 전환 `OnEnable`의 역할을 명확히 분배해야 성능 손실을 최소화할 수 있습니다.
- 오답 포인트: `Start`나 `Update`와 같이 단순한 메서드에 모든 부하 로직을 몰아넣는 나쁜 최적화 오개념을 짚어냅니다.
- 판별 기준: 데이터 로딩(Awake)과 시각적 장착(OnEnable)의 최적 역할 분배를 올바르게 서술한 B가 정답입니다.
