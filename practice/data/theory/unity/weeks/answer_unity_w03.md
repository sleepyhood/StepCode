|---|---|---|

| P02 | A | static 메서드 내부에서 클래스의 필드를 읽고 쓰려면, 해당 필드 역시 static이어야 함 |

## 해설
### P01
- 개념 정의: 메서드 선언 시 `void` 반환형은 작업 후 되돌려 줄 결괏값이 '아예 없음'을 뜻하며, 특정한 타입의 값을 돌려줄 때는 `int`, `GameObject` 등 구체적 자료형을 반환형으로 씁니다.
- 오답 포인트: 반환값이 없다는 것을 프로그래밍의 `null`(존재하지 않는 참조값)을 반환한다고 잘못 해석하는 실수가 매우 잦습니다. (`void`는 상태이며, `null`은 데이터 값입니다.)
- 판별 기준: `void`형이 아닐 때는 무조건 블록 내에 `return` 반환문이 필수적으로 존재해야 하는 언어적 제약을 이해하는지 판정합니다.

### P02
- 개념 정의: `static` 메서드는 특정 객체 인스턴스가 아니라 클래스 메모리 자체(Context)에 소속되어 실행됩니다.
- 오답 포인트: 클래스 내부에 같이 선언된 변수라는 이유만으로 아무 제약 없이 서로 변수 수정을 공유할 수 있다고 오해합니다.
- 판별 기준: `static` 멤버 함수 안에서 상태를 조작하려면 대상 변수(필드)도 반드시 `static`이어야 한다는 문맥(Context)의 일치성을 묻습니다.

### X01
- 개념 정의: C# 및 유니티에서 새로운 기능을 담당하는 함수(메서드)를 정의할 때는 문법적으로 약속된 '시그니처' 순서 규칙을 따라야 합니다.
- 오답 포인트: `static` 키워드를 빼먹거나 맨 끝으로 보내버리고, 반환형(`int`)과 메서드 이름(`Multiply`)의 위치를 거꾸로 쓰는 등의 기초 오류가 발생합니다.
- 판별 기준: `접근제어자`(`private`) -> `지정자`(`static`) -> `반환형`(`int`) -> `메서드명`(`Multiply`) -> `매개변수`(`(int a, int b)`)의 형태를 한 글자도 빠짐없이 조립했는지를 채점합니다.

### X02
- 개념 정의: 정적(`static`) 요소는 게임 전체(클래스 원형)에 단 하나만 존재하게 되며, 일반 멤버는 `Instantiate`나 `new`를 통해 복제된 붕어빵(인스턴스)마다 각각 소속됩니다.
- 오답 포인트: 초보자들은 흔히 객체라는 컨테이너를 구별하지 못하고 static 메서드에서 자기 클래스 내의 일반 인스턴스 멤버를 자유자재로 읽고 쓸 것이라 착각합니다.
- 판별 기준: static 메서드는 자기와 상관없는 개별 복제 객체의 속도, 체력 등에 직접 접근할 권한이나 참조가 전혀 없음을 완벽히 이해하는지 가려냅니다.
