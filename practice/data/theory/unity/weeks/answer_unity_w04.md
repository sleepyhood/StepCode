## 해설
### P01
- 개념 정의: `NullReferenceException` 런타임 에러는 메모리에 실제로 할당되지 않은 구체 없는 유령(`null`) 객체의 내부 속성이나 메서드(멤버 접근자 `.`) 등에 무언가 접근하려고 시도할 때 발생합니다.
- 오답 포인트: `new Book()`을 통해 겉 껍데기 객체 자체(`book`)는 분명히 생성되었으므로 `book`은 `null`이 아니지만, 이 과정에서 내부 멤버 `Author`까지 연쇄적으로 채워져서 생성되는 것은 아님을 혼동합니다.
- 판별 기준: 충돌이 난 줄 지점에서 단순히 표면적인 대상 뿐만 아니라 가장 핵심적으로 비어있는 실제 `null` 객체의 범위가 무엇인지 분리해서 찾아냅니다. (`book.Author`까지 추적)

### P02
- 개념 정의: 원본 메모리의 주소를 가리키고 보관하는 참조 객체(Reference Type, 클래스 인스턴스나 GameObject 등)는 할당되지 않은 상태인 `null` 값과 그 자체로 비교할 수 있는 능력이 있습니다. 값 복사 기반의 값 객체 타입(`int`, `bool` 등)은 태생적으로 `null`과 단독 비교할 수 없습니다.
- 오답 포인트: 겉모습이 유사해 보인다고 해서 원시 데이터 모델인 `bool` 등도 `null` 비교에 들어맞을 수 있다고 속단합니다.
- 판별 기준: `FindWithTag` 처리를 위해 대입되는 좌항과 `if`의 비교 대상인 `projectile` 변수 선언부가, `GameObject` 같은 완전한 유니티 기반 레퍼런스(참조) 타입 파생 요소인지 식별해야 합니다.

### P03
- 개념 정의: `==` 비교는 양쪽 변수가 메모리 상에서 서로 최소한의 공통된 본질 타입 형태를 가지고 있어야만 문법적인 전제가 성립합니다.
- 오답 포인트: 컴파일 단계에서 철저히 거부당하는 타입 미스매치 문법 에러와, 런타임 과정에서 값이 부족해 터지는 `null` 에러를 섞어 동일하게 판단하려 합니다.
- 판별 기준: 무수히 많은 원소들로 이루어진 `Dictionary`나 `List` 기반의 컬렉션 집합군과, 단일 원시형인 `int`나 `string` 사이의 무리한 데이터 상호 구조 비교 조합을 가려냅니다.

### P04
- 개념 정의: 컬렉션 매니저인 `Dictionary<T, T>`는 반드시 실체가 있는 객체로써 사용 전 메모리 런타임 주소 할당 초기화(`new()`)가 반드시 필요하며, 이후 반복문을 타고 데이터(`Key`-`Value`)를 넣어야만 안전하게 사용 가능합니다.
- 오답 포인트: 딕셔너리를 메모리에 구체화시키는 `dictionary = new (...)` 객체 초기화 과정을 대충 넘겨버리고, 대뜸 껍데기에 무조건 `Add` 작업부터 넣어서 Null 예외를 발생시킵니다.
- 판별 기준: `Dictionary`의 `new` 생성 -> 요소 추출(순회하는 `foreach` 구성) -> 순회 범위 내에서 각 단 건에 대한 `dictionary.Add(키, 값)` 등록 매핑이라는 정해진 시간순 절차를 맞추었는지 검증합니다.

### X01
- 개념 정의: `projectile == null ? A : B` 형태의 삼항 조건 연산자를 사용하면, 특정 객체가 비어있을 땐 안전한 기본값(Fallback)을, 온전히 존재할 땐 본래 의도한 로컬 변수 접근 등을 매우 간결하게 하나의 라인으로 결합하여 예외 처리를 대신할 수 있습니다.
- 오답 포인트: 유니티 환경에서 `null` 체크 과정 없이 객체 내부의 컴포넌트(`transform`) 변수에 무심코 즉시 하위 객체로 파고들었다가 NullReference 크래시(Crash)를 맞이합니다.
- 판별 기준: 조건 연산 단계에서의 철저한 `null` 필터링 과정, `true`일 때의 대안 처리(`0f`), 그리고 `false`로 이상이 없을 때의 명확한 `position.x` 참조 멤버 점검 경로를 확인합니다.

### X02
- 개념 정의: 실수와 정수처럼 태생이 숫자로만 이루어진 원시형 변수들끼리의 비교는 묵시성 기반의 캐스팅이 내재되어 있기 때문에 컴파일 논리 에러 없이 값의 대소 크기를 가늠(`>`, `<`)하는 것이 가능합니다.
- 오답 포인트: 배열 등 다른 타입에서는 호환이 막혀버리는 타입 체크 규칙을, 비교가 자유로운 원시 숫자 자료형들까지 통째로 확대 편향시켜서 컴파일이 안 된다고 오해합니다.
- 판별 기준: 호환 타입 쌍을 인지하여 타입 비교 연산자(`==`, `>`)가 유효하게 기능할 데이터 형태를 확신할 수 있어야 합니다.
