## 메타
- 대상 문제지: `problem_unity_w04.md`
- 유닛: U04 Null/Exception

## 정답표
| 문항 ID | 정답 | 한 줄 근거 |
|---|---|---|
| P01 | D | 새롭게 인스턴스화된 `book` 내부의 원시 멤버 속성인 `Author`가 아직 인스턴스화되지 않은 기본 `null` 상태임 |
| P02 | C | `GameObject`는 객체의 주소를 담는 참조 방식(Reference Type) 타입이므로 `null` 비교가 가능 |
| P03 | C | 1(Dict vs Int), 3(String vs List), 4(Dict vs List) 비교는 타입 불일치로 컴파일 자체가 불가능함 |
| P04 | B | 메모리에 컬렉션을 먼저 인스턴스화 생성(`D`)한 후 ➔ 대상 리스트 순회(`E`) ➔ 키-값 추가(`C`) ➔ 중괄호 닫기(`F`) |
| X01 | B | 삼항 연산자를 통한 null 안전 확인 검증 및 대안 값 할당 |

## 해설
### P01
- 개념 정의: `NullReferenceException` 런타임 에러는 메모리에 실제로 할당되지 않은 구체 없는 유령(`null`) 객체의 내부 속성이나 메서드(멤버 접근자 `.`) 등에 접근하려고 시도할 때 발생합니다.
- 오답 포인트: `new Book()`을 통해 겉 껍데기 객체 자체(`book`)는 생성되었으나, 내부 멤버 `Author`는 기본값인 `null` 상태임에 주의해야 합니다.
- 판별 기준: `book.Author` 객체가 `null`이므로, 여기에 다시 `.Age`를 찍은 D가 에러를 발생시킨 직접적인 원인입니다.

### P02
- 개념 정의: 원본 메모리의 주소를 가리키고 보관하는 참조 객체(Reference Type, 클래스 인스턴스나 GameObject 등)는 할당되지 않은 상태인 `null` 값과 그 자체로 비교할 수 있습니다.
- 오답 포인트: `bool`, `int`와 같은 값 타입(Value Type) 변수를 `null`과 등가 비교하려 하면 컴파일 에러가 발생합니다.
- 판별 기준: 참조 타입 변수(`projectile`)를 비교식에 정확히 사용한 C가 정답입니다.

### P03
- 개념 정의: C#에서는 구조가 완전히 이질적인 타입끼리 등가 비교(`==`)하는 것을 컴파일러 수준에서 차단합니다.
- 오답 포인트: 컴파일 단계에서 철저히 거부당하는 타입 미스매치 에러와, 실행 중 발생하는 런타임 예외를 구분해야 합니다.
- 판별 기준: 1, 3, 4번은 이종 타입 간의 비교이므로 컴파일 에러가 발생합니다. 숫자형 대소 비교(2, 5)는 가능합니다. 따라서 정답은 C입니다.

### P04
- 개념 정의: 딕셔너리를 사용하기 전에는 반드시 `new` 키워드로 힙 영역에 인스턴스를 생성해야 합니다.
- 오답 포인트: 인스턴스를 할당하지 않고 `Add`를 사용하면 `NullReferenceException`이 터집니다.
- 판별 기준: 딕셔너리 생성(D) ➔ `gameObjects` 리스트 순회(E) ➔ 딕셔너리에 추가(C) ➔ 중괄호 닫기(F) 순으로 진행되어야 합니다. 따라서 정답은 B입니다.

### X01
- 개념 정의: `조건 ? 참일때 : 거짓일때`를 활용해 삼항 연산자로 예외 발생을 방지할 수 있습니다.
- 오답 포인트: `projectile == null`일 때 0이 대입되어야 하며, 반대로 작성하거나 null 체크 전에 컴포넌트에 접근하면 에러가 납니다.
- 판별 기준: 객체가 null인지 선검사하고 안전한 0을 먼저 대입하는 구조인 B가 정답입니다.

### X02
- 개념 정의: 실수와 정수처럼 태생이 숫자로만 이루어진 원시형 변수들끼리의 비교는 묵시성 기반의 캐스팅이 내재되어 있어 비교 연산이 성립합니다.
- 오답 포인트: 객체 타입간 등가 비교 불가 규칙을 숫자형 자료형들까지 동일하게 대입하는 착각이 잦습니다.
- 판별 기준: 묵시적 형변환이 일어나는 `myFloat > myInt` (D)는 컴파일 에러 없이 연산됩니다.
