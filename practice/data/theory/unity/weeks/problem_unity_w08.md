## 원문 대응 문항
### [P01] UI Text에 점수를 표시하기 위한 필수 3요소 작성
- 출처: 원문 6번
- 유형: 단답
- 문제:
  - 게임 화면에 현재 점수(`score` 변수, 정수형)를 유니티 UI의 `Text` 컴포넌트를 통해 실시간으로 표시하려고 합니다.
  - 이를 위해 C# 스크립트에 반드시 포함되어야 하는 **핵심 코드 3요소**를 각각 정확한 C# 문법으로 작성하세요.
  - 요구 항목:
    - ① 유니티의 UI 관련 클래스(`Text` 등)에 접근하기 위해 스크립트 최상단에 선언해야 하는 네임스페이스 `using` 구문
    - ② `Text` 컴포넌트를 Inspector에서 드래그 연결할 수 있도록 클래스 멤버로 선언하는 변수 선언문 (변수명: `myText`)
    - ③ 점수가 갱신된 후, 숫자(`score`)를 문자열로 변환하여 UI 텍스트에 반영하는 대입 코드 한 줄 (포맷: `"Score: 값"`)

### [P02] 문자열 표시 메서드(SetMessageToDisplay) 선언 시그니처 완성
- 출처: 원문 7번
- 유형: 단답
- 문제:
  - 외부에서 `SetMessageToDisplay("게임 오버!")` 형태로 호출하면, 내부에서 `textToDisplay.text = stringToDisplay;` 코드를 실행하여 화면에 메시지를 띄우는 메서드를 만들려 합니다.
  - 이 호출 형태와 내부 본문 코드가 **동시에 컴파일 오류 없이 작동**하도록, 메서드 선언부에 들어갈 3가지 시그니처 요소를 각각 쓰세요.
  - 요구 항목:
    - ① 반환형: 이 메서드는 화면에 텍스트를 설정하기만 하며 호출자에게 값을 돌려주지 않습니다.
    - ② 메서드명: 호출 코드와 정확히 대소문자까지 일치해야 합니다.
    - ③ 매개변수: 본문에서 `stringToDisplay`라는 이름으로 참조되는 문자열 파라미터를 받아야 합니다.

### [P03] OnMouseUp 패널 토글 함수 선언부 완성
- 출처: 원문 16번
- 유형: 단답
- 문제:
  - 유니티에서 3D/2D 오브젝트 위에 마우스 버튼을 눌렀다가 **뗐을 때** 자동으로 호출되는 엔진 내장 메시지 함수를 선언하여 UI 패널 표시를 토글하려고 합니다.
  - 이 메시지 함수는 외부 스크립트에서 직접 호출할 필요 없이 엔진이 내부적으로만 호출하므로, 접근 범위를 최소한으로 제한해야 합니다.
  - 아래 선언부의 빈칸 3개를 채우세요.
  - `[①] [②] [③]() { panelObject.SetActive(!panelObject.activeSelf); }`
  - 요구 항목:
    - ① 접근 제한자: 외부 노출 불필요 → 가장 좁은 범위
    - ② 반환형: 패널을 토글만 하고 값을 돌려주지 않음
    - ③ 메서드명: 유니티 엔진이 마우스 버튼을 뗐을 때 자동 호출하는 정확한 내장 함수 이름

### [P04] 버튼 이벤트 등록 위치에 따른 동작 참/거짓 판별
- 출처: 원문 30번
- 유형: 참거짓
- 문제:
  - 유니티 UI Button의 `onClick.AddListener(콜백함수)`를 **어떤 메서드 안에서 호출하느냐**에 따라 동작 안정성이 결정됩니다. 다음 3가지 시나리오의 참/거짓을 판별하세요.
  - 문장 1: 씬이 시작될 때 **단 1회**만 호출되는 `Start()` 내부에서 `button1.onClick.AddListener(MyFunc);`을 등록하면, 이후 `button1`을 클릭할 때마다 `MyFunc`이 정상적으로 1번씩 실행된다.
  - 문장 2: `OnTriggerEnter2D(Collider2D other)`는 물리 충돌 감지 전용 엔진 이벤트이지만, 이 안에서 `button3.onClick.AddListener(MyFunc3);`를 호출하면 **UI 버튼 클릭과 동일한 효과**를 얻을 수 있다.
  - 문장 3: 매 프레임 반복 호출되는 `Update()` 안에서 `button2.onClick.AddListener(LightBulbOn);`을 등록하면, 리스너가 매 프레임 **중복 누적**되어 클릭 1회에 `LightBulbOn`이 수십~수백 번 실행되는 치명적 부작용이 생기지만 동작 자체는 한다.
  - 답안 형식 예: `1 참, 2 거짓, 3 참`

## 확장 문항 (변형/함정/응용)
### [X01] 변형 - UI 버튼 리스너 안전한 1회 등록 코드 작성
- 출처 개념: U08 UI
- 유형: 코드
- 문제:
  - Inspector에 연결된 `Button button2` 변수가 있고, 이 버튼을 클릭하면 같은 스크립트 안의 `LightBulbOn` 메서드가 실행되어야 합니다.
  - **씬 시작 시 정확히 1번만 리스너가 등록**되어 중복 실행 부작용이 절대 없도록 하는 완전한 코드 블록을 작성하세요.
  - 작성 조건:
    - 리스너 등록을 감싸는 메서드 컨테이너(`void Start()` 등)를 포함하여 작성할 것.
    - `AddListener` 호출 시 괄호 안에 콜백 메서드명을 정확히 기입할 것.
- 의도: `Update()`나 `OnTriggerEnter2D()` 등 반복 호출 구간이 아닌, `Start/Awake/OnEnable` 같은 1회성 초기화 메서드에서만 리스너를 등록해야 하는 원칙을 코드로 직접 증명하게 합니다.

### [X02] 함정 - AddListener 최적 등록 위치 판별
- 출처 개념: U08 UI
- 유형: 객관식
- 문제:
  - 게임 씬에 단일 UI 버튼이 하나 있고, 클릭 시 특정 기능을 발동시키려 합니다. 리스너가 **중복 등록되어 1회 클릭에 콜백이 여러 번 호출되는 사고**를 원천 차단하기 위해, `button.onClick.AddListener(콜백)`을 배치할 **가장 안전하고 적절한 유니티 생명주기 메서드**를 고르세요.
- 보기:
  - A. `Update()` — 매 프레임마다 호출되어 시각적 갱신에 최적화된 루프
  - B. `Start()` — 씬 시작 시 해당 스크립트에서 단 1회만 호출되는 초기화 메서드
  - C. `OnTriggerEnter2D()` — 2D 물리 충돌 감지 시마다 호출되는 이벤트
  - D. `LateUpdate()` — 매 프레임 `Update()` 직후에 호출되는 후처리 루프
- 의도: 매 프레임 반복 호출되는 루프 메서드(`Update`, `LateUpdate`)나, 물리 충돌이라는 전혀 다른 조건에 의해 불규칙하게 호출되는 이벤트(`OnTriggerEnter2D`)에 리스너를 넣었을 때의 폭발적 중복 등록 위험을 인지하고, 1회성 초기화 전용 메서드를 정확히 판별하게 합니다.
