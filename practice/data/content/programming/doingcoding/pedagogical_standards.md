# StepCode — 교육적 품질 표준 (Pedagogical Standards)

이 문서는 StepCode의 문제 콘텐츠가 **"선생님 없이도 학생이 혼자 이해할 수 있는 수준"**을 유지하되, **학생의 독해력 피로를 방지하고 제작 효율성을 극대화**하기 위한 표준을 정의합니다.

문제를 만드는 사람은 답을 이미 알기 때문에 설명이 장황해지거나 논리적 비약을 느끼지 못합니다. 이를 **전문가의 저주(Expert Blindness)**라고 합니다. 반대로, 모든 문제에 동일하게 무거운 기준(상세 설명, 다이어그램, 다단계 힌트)을 강제하면 학습자가 질리고 제작 효율이 떨어지는 **규정의 저주(Over-Regulation)**에 빠집니다.

이 문서는 이를 방지하기 위한 **3단계 문제 티어링(Problem Tiering)**과 티어별 최적화된 감사/개선 가이드를 제공합니다.

> **적용 대상**: `content_production_pipeline.md`의 **Phase 6: 교육 품질 검토** 단계.

---

## 1. 문제 유형별 3단계 티어(Tier) 정의

모든 문제에 시각 자료와 상세한 힌트가 들어갈 필요는 없습니다. 문제의 난이도와 역할에 맞춰 가독성을 최적화합니다.

### 🟢 티어 1: 튜토리얼 / 개념 입문형 (Tutorial / Concept Intro)
*   **대상**: 단원이나 대주제에서 **새로운 개념/자료구조/동작 원리**를 처음 접하게 하는 1~2개의 핵심 문제 (예: 스택 튜토리얼, 재귀함수 시작 등).
*   **분량 규칙**: 충분한 개념 비유와 흐름을 담되, 줄글보다는 이미지와 레이아웃으로 분량 부담을 덜어줍니다.
*   **시각 자료 (⭐1)**: **필수** (Mermaid 호출 트리, 데이터 흐름 다이어그램, 실세계 비유 이미지 등 최소 1개 이상).
*   **예제 추적 (⭐2)**: **필수** (예제 1번 입력에 대한 컴퓨터의 한 단계씩 동작 흐름 추적).
*   **힌트 전략 (⭐4)**: **필수** (직접적인 정답 코드가 아니며, **원리는 동일하여 응용하면 정답을 유도할 수 있는 유사한 코드나 간결한 개념적 힌트**를 제시).
*   **YAML 설정**: `has_hint: "true"`

### 🟡 티어 2: 표준 연습형 (Standard Exercise)
*   **대상**: 개념을 익힌 후, 단순 반복 또는 경미한 조건 변경을 통해 손에 익히는 대부분의 일반 문제 (예: N부터 1까지 출력, 스택 명령어 처리 등).
*   **분량 규칙**: **극도의 슬림화**. 설명은 **5~10줄 이내**로 제한. 학생이 본문을 보자마자 3초 이내에 요구사항을 파악할 수 있어야 합니다.
*   **시각 자료 (⭐1)**: **생략 권장** (지문 이해에 필수적인 경우 제외).
*   **예제 추적 (⭐2)**: **생략 권장** (입출력이 자명하고 직관적이므로 불필요).
*   **힌트 전략 (⭐4)**: **생략 권장** (문제 해결에 숨겨진 트릭이 없다면 굳이 힌트를 지어내지 않음).
*   **YAML 설정**: `has_hint: "false"` (공식 권장 및 기본값)
    *   *예외*: 특정 경계값 처리나 잔실수가 잦은 지점(예: 줄바꿈, 빈칸 출력 등)이 있다면 **1줄 이내의 간단 팁**만 제공 가능.

### 🔴 티어 3: 심화 도전형 (Challenge / Application)
*   **대상**: 예외 처리, 수학적 아이디어, 알고리즘 최적화가 필요한 변별력 문제.
*   **분량 규칙**: 핵심 비즈니스 로직과 제약 조건, 예외 상황을 명확하고 건조하게 전달하는 데 집중.
*   **시각 자료 (⭐1)**: **전략적 사용** (도형 기하 로직이나 복잡한 3차원 분기에서만 사용).
*   **예제 추적 (⭐2)**: **선택적 사용** (학생들이 가장 많이 틀리는 '함정/반례 예제'가 왜 그런 결과로 이어지는지 추적하는 용도로만 짧게 작성).
*   **힌트 전략 (⭐4)**: **최소화** (직접적인 의사코드나 상세 설명 없이, 사고의 방향을 슬쩍 틀 수 있는 **모호하고 유용한 1줄 팁이나 유사 응용 예시**만 짧게 제시).
*   **YAML 설정**: `has_hint: "false"` 또는 `"true"`

## 2. 조건부 5성급 품질 기준 (Tiered 5-Star Standard)

| 번호 | 기준 | 체크 포인트 | 실패 신호 | 적용 범위 |
|:---:|:---|:---|:---|:---|
| ⭐1 | **전략적 시각 자료** | 새로운 개념의 도입부이거나, '그림'이 없으면 이해가 어려운가? | 입문용 튜토리얼이나 기하 문제임에도 시각 자료가 전혀 없다 | **티어 1 필수** / 티어 2, 3 선택 |
| ⭐2 | **예제 추적** | "왜 이 입력이 이 출력이 되는지" 단계별로 설명이 되어 있는가? | 예제 결과가 특이하거나 흐름이 복잡한데 왜 그런지 설명이 없다 | **티어 1 필수** / 티어 2 생략 / 티어 3 선택 |
| ⭐3 | **개념 중립성** | 특정 언어(예: C)에만 종속된 문법 표현을 알고리즘 설명에 쓰고 있지 않은가? | C 코드 이미지만 제공되어 Python/Java 학생이 이해하지 못한다 | **모든 티어 필수** |
| ⭐4 | **간결하고 유용한 힌트** | 힌트가 "정답 스포일러"나 "상세 설계도"가 아닌 **"응용 가능한 유사 정보/방향성"**을 던져주는가? | 힌트가 문제를 대신 풀어주거나 정답 의사코드가 1:1로 매핑되어 있다 | **티어 1 필수** / 티어 2, 3 선택 |
| ⭐5 | **전략적 예제** | 단순 수치 나열이 아닌, '원리 이해용'과 '함정 돌파용(반례)' 예제가 구별되는가? | 예제가 너무 단순하여 문제의 특이 케이스를 검증하지 못한다 | **모든 티어 권장** |
| ⭐6 | **단일 페르소나** | 문서 전체가 정제된 전문 강사 한 명이 설명하는 톤을 유지하는가? | 구어체 설명 뒤에 갑자기 조잡하거나 어색한 AI 표/텍스트가 등장한다 | **모든 티어 필수** |

## 3. 감사 프롬프트 모음 (Audit Prompts)

AI에게 문제 본문을 제공하고, 아래 프롬프트를 함께 사용하여 검증합니다.

### 🔍 Prompt A — 가독성 및 장황성 감사 (초보자 페르소나)
> **용도**: 전문가의 저주를 깨고, 텍스트가 쓸데없이 길어 학생들이 포기하는 지점 탐지.

```
[ROLE] 너는 이제 막 반복문을 배운 14세 입문자야. 너는 모르는 단어가 나오면 금방 의욕을 잃고, 문제 지문의 설명이 쓸데없이 길어지면 읽기를 포기해.

[TASK] 아래 문제 지문을 읽고, 다음 질문에 솔직하게 대답해줘.
1. "이해가 안 가거나 머리가 복잡해지는 단어/문장" (최대 2개)
2. "이 문제는 너무 길어서 읽기 싫다"라고 느끼게 만드는 장황한 설명 부분
3. 이 문제를 더 짧고 간결하게 줄이기 위해 삭제해야 할 구절 제안
```

---

### 🔍 Prompt B — 언어 중립성 감사
> **용도**: C 코드나 특정 언어 문법에만 의존하는 구절 발견.

```
[ROLE] 너는 Python만 배운 입문자야. C언어를 전혀 모른다.

[TASK] 아래 문제를 읽고, 다음을 지적해줘.
1. 문제 본문이나 설명 중에 C언어를 모르면 이해하기 힘든 표현(예: printf, scanf, std::stack 등)이 포함되어 있는가?
2. 특정 언어 편향 없이, 개념 중심의 공통 알고리즘 로직으로 대체할 수 있는 대안을 제시해줘.
```

---

### 🔍 Prompt C — 힌트 품질 및 모호성 감사
> **용도**: 불필요한 힌트로 문서가 뚱뚱해지거나 정답 코드를 다 보여주는 것 방지.

```
[TASK] 이 문제의 난이도와 아래 [힌트 규칙]을 참고하여, 현재 작성된 힌트가 적절한지 감사해라.

[힌트 규칙]
1. 정답 코드나 정답용 의사코드(Pseudocode)를 직접 누출해서는 안 된다.
2. 힌트는 **"정답은 아니지만, 원리가 같아 응용하면 정답을 도출할 수 있는 유사한 지식/예시"**를 간결하게 던져주어야 한다.
3. 텍스트가 장황하지 않고 직관적이어야 한다.

현재 힌트가 이 규칙에 부합하는가? 힌트가 너무 직접적이어서 스포일러가 되거나, 혹은 반대로 학습자에게 아무 쓸모도 없는 무의미한 조언인지 지적하고 간결화 방향을 제시해라.
```

## 4. 개선 프롬프트 모음 (Improvement Prompts)

문제를 수정하거나 새로 작성할 때 AI에 제공하는 프롬프트입니다.

### 🛠️ Prompt D — 예제 추적(Trace) 추가 (티어 1 및 복잡한 문제용)
> **용도**: "왜 이 입력이 이 출력이 되는지" 컴퓨터의 사고 과정 추가 (단, 중복 텍스트는 철저히 제거).

```
[TASK] 아래 문제의 예제 1번에 대해 컴퓨터의 생각 과정을 작성해줘.

[제약 조건]
- 이 문제는 티어 1(입문) 또는 로직 추적이 필수적인 문제입니다.
- 기존 본문에 있는 중복 설명을 제거하고 자연스럽게 통합할 것.
- H3 헤더인 `### 🖥️ 예제 1 추적 (N = 10일 때)` 과 같은 형태로 작성하되, 새로운 H2(##) 헤더는 절대 생성하지 마라.
- 표나 리스트를 이용해 5단계 이하의 흐름으로 간결하고 명확하게 쓸 것.
- 정답 코드를 스포일러하지 마라.
```

---

### 🛠️ Prompt E — Mermaid 시각화 추가 (시각화 대상 문제용)
> **용도**: 공간/구조 이해를 돕는 다이어그램 삽입 (티어 1 및 기하 로직 한정).

```
[TASK] 아래 문제의 핵심 동작을 Mermaid 다이어그램으로 시각화해줘.

[제약 조건]
- 다이어그램 삽입 전, 다이어그램을 설명하는 브릿지 문장을 1줄 내외로 작성해라.
- 노드는 한글을 사용하고, 5개 이하로 단순화하여 구조적 핵심만 보여줘라.
- 복잡하게 모든 호출 흐름을 다 그리지 말고, 동작의 '원리'만 직관적으로 알 수 있게 해라.
```

---

### 🛠️ Prompt F — 간결성/모호성 지향 힌트 재작성
> **용도**: 힌트의 세부 설계를 걷어내고, 문제를 직접 풀지 않고도 응용할 수 있는 힌트만 간결하게 남김.

```
[TASK] 아래 문제의 티어를 분석하여 힌트 섹션을 재작성해라.

[작성 로직]
1. 문제 난이도가 낮고 티어 2(연습)인 경우:
   - 힌트를 전면 생략하고 다음 문구만 남긴다.
   (힌트가 없습니다.)
   - YAML의 has_hint를 "false"로 설정.

2. 문제의 실수 유발 포인트가 있어 팁이 필요한 경우:
   - 1줄짜리 가벼운 팁만 제공한다.
   ### 💡 팁
   - 주의: 공백이나 빈칸 출력이 올바른지 다시 확인해보세요.
   - YAML의 has_hint를 "false"로 설정.

3. 문제 난이도가 높은 경우(티어 1 또는 일부 티어 3):
   - **정답 코드의 설계도가 아닌, 원리가 동일해 응용할 수 있는 간결한 힌트**를 제공한다.
   - 포맷:
     ### 💡 힌트 1 (방향) — [짧은 생각 거리 던지기]
     ### 💡 힌트 2 (응용 예시) — [정답과 직접 겹치지 않지만 원리가 동일해 응용할 수 있는 예시나 유사 개념 짧게 설명]
   - YAML의 has_hint를 "true"로 설정.

[제약 조건]
- 정답용 의사코드(Pseudocode)나 상세 알고리즘 구현 단계를 제공하지 마라.
- 텍스트 길이를 최소화하고, 학생들이 힌트를 읽고 스스로 응용 방안을 생각해낼 수 있도록 모호성을 다소 남겨라.
```

## 5. 작성 및 수정 시 절대 준수 사항 (Mandates)

1.  **헤더 구조 유지**: 모든 문제 MD 파일은 아래 4개의 H2 헤더를 무조건 유지합니다. 내용이 없더라도 헤더를 삭제해서는 안 됩니다.
    *   `## 1. 문제 설명`
    *   `## 2. 입출력 설명`
    *   `## 3. 예시`
    *   `## 4. 힌트`
2.  **힌트 부재 시 표기**: 힌트가 없는 경우(`has_hint: "false"`), `## 4. 힌트` 바로 아랫줄에 반드시 `(힌트가 없습니다.)` 한 줄만 남겨놓습니다.
3.  **예시 섹션의 순수성**: `## 3. 예시` 섹션에는 `### 예시 입력 n`과 `### 예시 출력 n` 형식의 코드 블록 외에 어떠한 설명글도 적지 않습니다. 파서의 오동작을 막기 위함입니다.
4.  **슬림화 우선주의 (Brevity First)**: 설명글을 읽는 것 자체가 학생에게는 노동입니다. 가능한 텍스트를 쪼개지 말고, 간결하고 명확한 문장으로 합치십시오. 티어 2 연습 문제는 5~10줄 내로 끝내야 합니다.
5.  **언어 중립성 확보**: C, Python, Java를 쓰는 학생들이 모두 지문을 읽고 이해해야 하므로 특정 언어의 전용 API 명칭보다는 개념적 명칭(예: "출력 함수", "스택 삽입 연산")을 사용하십시오.

## 6. Phase 6 최종 게시 전 체크리스트

각 문제의 티어를 먼저 파악한 후, 해당하는 항목들만 통과하면 즉시 완료 처리합니다.
