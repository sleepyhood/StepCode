# 18. [클래스와 상속 - 18] 실전 응용: 전략 패턴

## 1. 문제 설명

실무에서 인터페이스를 사용하는 가장 결정적인 이유는 **코드 간의 결합도(Coupling)를 낮추어 유지보수성을 극대화하기 위함**입니다.
어떤 클래스가 구체적인 구현 클래스에 직접 의존하지 않고 오직 인터페이스 규격에만 의존하게 만들면, 프로그램 실행 도중에도 알고리즘이나 비즈니스 규칙(전략)을 부품 갈아 끼우듯 자유롭게 교체할 수 있습니다. 이를 객체지향 디자인 패턴에서는 **전략 패턴(Strategy Pattern)**이라고 부릅니다.

쇼핑몰의 주문 결제 시스템을 구현하세요.
- 할인 전략 규격: `DiscountPolicy` 인터페이스
  - `calculateDiscount(int price)`: 원가(`price`)를 받아 할인 금액을 계산하여 반환
- 구현 전략 클래스:
  - `FixedDiscountPolicy`: 고정 금액 `F`원 할인. (단, 할인액이 원가를 초과할 경우 원가만큼만 할인되어 결제 금액이 음수가 되지 않아야 합니다.)
  - `RateDiscountPolicy`: 원가의 `R`% 정률 할인. (`price * R / 100`, 정수 연산)
  - `NoDiscountPolicy`: 할인액 0원 반환
- 주문 처리기 `OrderProcessor`:
  - `DiscountPolicy` 인터페이스 타입의 멤버를 보유합니다.
  - `setPolicy(DiscountPolicy policy)`: 할인 전략을 동적으로 교체 주입합니다.
  - `getFinalPrice(int price)`: 원가에서 계산된 할인액을 차감한 최종 결제 금액을 반환합니다.

## 2. 입출력 설명

- **입력:**
  - 첫 번째 줄에 원래 상품 가격 정수 `Price`가 주어집니다. (1 ≤ Price ≤ 1,000,000)
  - 두 번째 줄에 할인 전략 타입 정수 `Type`이 주어집니다.
    - `1` → 고정 정액 할인 (`FixedDiscountPolicy`)
    - `2` → 정률 퍼센트 할인 (`RateDiscountPolicy`)
    - `3` → 할인 없음 (`NoDiscountPolicy`)
  - 세 번째 줄에 전략별 세부 수치 `Param`이 주어집니다.
    - `Type == 1`인 경우: 정액 할인액 `F` (0 ≤ F ≤ 1,000,000)
    - `Type == 2`인 경우: 할인율 `R` (0 ≤ R ≤ 100)
    - `Type == 3`인 경우: `0`

- **출력:**
  - 첫 번째 줄에 할인된 금액을 `Discount: [할인금액]` 형식으로 출력합니다.
  - 두 번째 줄에 최종 결제 금액을 `Final Price: [최종금액]` 형식으로 출력합니다.

## 4. 힌트

- **핵심 아이디어**: 정액 할인 시 원가보다 할인액이 큰 경우(예시 3번) 최종 금액이 음수가 되지 않도록 `Math.min(price, F)` 처리를 잊지 마세요.
- **생각해볼 점**:
  1. `OrderProcessor` 내부 코드에 구체 클래스(`FixedDiscountPolicy` 등) 이름이 직접 하드코딩되어 있지 않고, `DiscountPolicy` 인터페이스 타입으로만 다루어지고 있는가?
