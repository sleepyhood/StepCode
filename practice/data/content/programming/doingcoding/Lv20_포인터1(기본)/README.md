## 3. 입출력 꼼수 방지(Bypass Prevention) 설계 계획

지문 제약만으로는 포인터를 쓰지 않고 통과하는 우회(Hardcoded print)가 가능하므로, **런타임 입출력 구조 자체에서 포인터 연산을 강제**하도록 설계합니다.

| 문항 ID | 기존 취약점 (꼼수 방식) | Phase 3 반영 입출력 꼼수 방지 설계안 |
|:---|:---|:---|
| **`P102v2001`** | 단순 정수 입출력 → 일반 변수 `printf`로 통과 | 입력 $A$와 가산값 $K$를 받아, 포인터 $p$를 통해 `*p += K` 수행 후 최종 값 출력 (간접 수정 검증) |
| **`P102v2002`** | 10 입력에 무조건 20 출력 → `printf("20\n")` 우회 | 두 변수 $A, B$ 중 수정 대상(1 또는 2)과 새 값 $V$를 받아, 포인터 바인딩 후 값 변경 확인 |
| **`P102v2003`** | 입력 없음 → 단순 문자열 출력으로 통과 | 배열 원소 3개를 입력받고, 배열 시작 포인터 `p`를 이용해 `*(p + i)` 형식으로 순차 출력 |
| **`P102v2004`** | 5개 입력 후 단순 순회 → 일반 `arr[i]`로 우회 | 배열 입력 후, 포인터 이동 연산으로 순회하며 짝수 원소에만 배수를 적용하는 인플레이스 가공 강제 |
| **`P102v2005`** | 입력 없음 → `printf("hello\n")` 한 줄 우회 | 문자열 포인터를 유지하되, 포인터 이동을 통해 첫 글자를 건너뛴 부분 문자열 출력 유도 |
| **`SP102v2001`**<br/>(숙제 1) | 단순 출력 순서 변경 → `printf("%d %d", b, a)` | 교환 후 연산 플래그 $Op$를 받아 특정 포인터가 가리키는 방의 최종 값을 동적 조회 |
| **`SP102v2002`**<br/>(숙제 2) | 단순 반대 for 루프 → `arr[n-1-i]` 우회 | 배열의 끝 주소 포인터(`arr + n - 1`)를 초기화하여 포인터 감소 연산(`p--`)으로 출력 |
| **`SP102v2003`**<br/>(숙제 3) | 단순 max 값 출력 → 인플레이스 미수행 | 최댓값 위치를 가리킨 포인터에 보너스 $X$를 더한 뒤, 동적 인덱스 $K$를 받아 `arr[K]`를 확인 |
