## 1. 현재 최종 방향

1주차는 더 이상 `잘게 쪼갠 미션 8개` 중심이 아니라,
`6개 대문항 x 각 4개 소문항` 구조의 문제지 세트로 재구성되었다.

핵심 원칙:

- 학생에게 `문제 파일(.py)`은 직접 제공하지 않는다.
- 학생은 `문제지의 제시 코드`를 직접 입력하고 풀이한다.
- 모든 대문항은 `누적풀이`를 전제로 한다.
- 즉, 앞 소문항을 해결하지 못하면 뒤 소문항도 자연스럽게 막히는 구조를 의도한다.
- 정답 형식은 최대한 자동채점 가능한 형태로 제한한다.

현재 허용된 형식:

- `코드 입력형`
- `빈칸형`
- `복수정답 객관식형`

제외한 방향:

- 자유 서술형 자연어 정답
- 2줄 이상을 강요하는 코드 입력형
- 소문항마다 별도 전체 코드 반복 제시

## 4. 지금 시점의 중요한 판단

### 4-1. 문제파일 미제공 전략 유지

현재 판단은 유지:

- 학생에게 `.py` 파일을 직접 주지 않는 방향이 맞다.
- 문제지의 제시 코드를 보고 직접 타이핑하게 만드는 것이 체류시간 확보와 이해도 확인에 더 유리하다.

즉:

- 검수/제작용으로는 `problem*.py` 유지
- 학생 배포용으로는 `문제지에 코드 제시 + 학생 직접 입력`

### 4-2. 대문항 중심 구조 유지

현재 문제는 `소문항만 독립 카드처럼 소비하는 구조`가 아니라
반드시 `대문항 -> 공통 코드/설명 -> 소문항` 구조여야 한다.

그래서:

- JSON도 `sections`
- 웹 렌더러도 `sections`
- 문제지도 대문항 중심

이 방향으로 맞췄다.

### 4-3. 누적풀이를 일부러 유지

현재는 의도적으로:

- 앞 문항이 뒤 문항의 전제가 되는 구조
- 즉, 앞에서 막히면 뒤도 풀기 어려운 구조

를 유지한다.

이것은 실수나 미완성이 아니라 설계 의도다.
