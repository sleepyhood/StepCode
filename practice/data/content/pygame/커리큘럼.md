# pygame 6주 응용 문제 커리큘럼

## 기준

- 대상: 파이썬 기초 문법을 마친 학생
- 수업 시간: 회당 90분
- 운영 목표: pygame API를 길게 설명하기보다, 제시 코드를 읽고 수정하며 동작을 완성하는 능력을 기른다
- 운영 방식: `짧은 개념 확인 -> 고장난 코드 수정 -> 응용 문제 풀이 -> 결과 비교`
- 문제 형식: `코드 입력형`, `빈칸형`, `복수정답 객관식형` 중심

이 커리큘럼은 `개념 주차 + 응용 주차`를 따로 나누지 않습니다.
모든 주차를 `응용 문제 중심`으로 운영합니다.

즉, 매 주차의 핵심은 아래와 같습니다.

- 왜 화면이 안 뜨는지 찾기
- 왜 종료가 안 되는지 찾기
- 왜 좌표가 어긋나는지 찾기
- 왜 입력 규칙이 잘못 동작하는지 찾기
- 어떤 숫자/조건을 바꾸면 결과가 어떻게 달라지는지 설명하기

## 운영 원칙

- 새 문법 설명은 최소한으로 두고, 바로 문제에 연결합니다.
- 학생이 코드 전체를 처음부터 작성하기보다, 이미 주어진 코드를 읽고 고치는 경험을 반복합니다.
- 한 주차 안에서 다루는 주제는 많아도, 문제 구조는 통일해서 인지 부담을 줄입니다.
- 한 주차의 핵심 문항은 `4개 내외의 소문항 묶음`으로 관리합니다.
- `결과 예측`과 `수정 후 동작 설명`을 반드시 포함해, 단순 타이핑이 아니라 코드 해석 능력을 확인합니다.

## 1~6주 운영안

### 1주차: 화면 구성 기초 응용

범위:

- `round01`의 `1~4번`만 사용

주제:

- 창 생성
- `fill()`
- `pygame.display.update()`
- 종료 처리
- 좌표와 도형 배치

학습 목표:

- 화면이 왜 안 보이거나 안 바뀌는지 찾을 수 있다.
- 좌표를 수정해 원하는 화면 결과를 만들 수 있다.
- 종료가 안 되는 코드를 정상 동작으로 복구할 수 있다.

운영 메모:

- `problem_review_round01.md`의 `1~4번`을 1주차 핵심 세트로 본다.
- 기존의 `1주차에 1~6번 전체를 넣는 해석`은 사용하지 않는다.
- 1주차는 `화면/종료/갱신/좌표`의 기본 응용 문제만 다룬다.

### 2주차: 이미지 출력과 회전 응용

범위:

- 기존 `round01`의 `5번`을 확장 이관

주제:

- 이미지 출력
- 회전 결과물의 중심 보정
- 좌표 기준
- `get_rect(center=...)`

학습 목표:

- `(0, 0)` 기준 출력 문제를 발견하고 수정할 수 있다.
- 회전 결과가 왜 어색하게 보이는지 설명할 수 있다.
- 중심 좌표 보정이 화면 결과를 어떻게 바꾸는지 이해할 수 있다.

운영 메모:

- `새 개념 설명`보다 `이상한 회전 결과를 정상 동작으로 바꾸는 문제 세트`로 해석한다.
- 자산 사용 자체보다 `출력 위치와 중심 보정`을 핵심으로 둔다.

### 3주차: 마우스 입력과 그리기 규칙 응용

범위:

- 기존 `round01`의 `6번`을 확장 이관

주제:

- `MOUSEMOTION`
- 클릭 상태 조건
- 좌표 저장
- 반복 출력

학습 목표:

- 입력 조건이 빠진 코드를 읽고 원하는 규칙으로 수정할 수 있다.
- 저장된 좌표를 화면 출력과 연결할 수 있다.
- 조건 하나가 입력 동작 전체를 어떻게 바꾸는지 설명할 수 있다.

운영 메모:

- 그림판 완성보다 `입력 규칙 수정형 문제`에 초점을 둔다.
- 클릭 여부, 좌표 저장, 반복 출력의 연결을 문제로 확인한다.

### 4주차: 이동과 값 변화 응용

범위:

- `x/y` 이동
- 색 변화
- 속도 조절
- FPS 비교

주제:

- 이동량 변경
- 좌표 누적
- FPS와 체감 속도
- 값 변화에 따른 화면 결과

학습 목표:

- 숫자 하나가 화면 동작을 어떻게 바꾸는지 해석할 수 있다.
- 왜 더 빠르거나 느리게 보이는지 코드 기준으로 설명할 수 있다.
- 이동과 색 변화처럼 여러 값이 동시에 바뀌는 상황을 읽을 수 있다.

운영 메모:

- 기존 1주차의 `3번` 계열 문제를 확장 응용 주차로 재사용할 수 있다.
- 핵심은 `움직임 구현`보다 `값 변화 읽기와 수정`이다.

### 5주차: 이벤트와 상태 분기 응용

범위:

- 키 입력
- 상태값
- 조건 분기
- 간단한 규칙 전환

주제:

- 이벤트 처리 흐름
- 조건 분기
- 상태에 따른 다른 화면 결과

학습 목표:

- 입력과 상태를 연결해서 동작을 바꿀 수 있다.
- 조건 하나 추가 또는 변경 형태의 응용 문제를 풀 수 있다.
- 현재 상태값이 어떤 결과를 만드는지 설명할 수 있다.

운영 메모:

- 복잡한 설계 이론보다 `분기 수정형 문제` 중심으로 설계한다.
- if문을 새로 설명하기보다, 이미 아는 조건문을 pygame 상황에 적용하는 방식으로 운영한다.

### 6주차: 미니게임 조립형 종합 응용

범위:

- 앞 주차 요소를 조합한 종합 문제

주제:

- 화면 갱신
- 입력 처리
- 좌표 이동
- 조건 판정
- 간단한 점수 또는 목표 규칙

학습 목표:

- 부분 기능이 고장난 미니게임 코드를 단계적으로 복구할 수 있다.
- 단일 문법이 아니라 여러 요소를 연결해 해석할 수 있다.
- 수정 전후의 동작 차이를 코드와 결과 화면으로 설명할 수 있다.

운영 메모:

- `완성형 강의안`보다 `종합 응용 문제 세트`에 가깝게 설계한다.
- 앞 주차에서 다룬 수정 포인트를 한 문제 안에 다시 조합한다.

## 7~10주 확장 운영안

### 7주차: 랜덤 모듈 응용

범위:

- `random.randint`
- `random.choice`
- 랜덤 위치
- 랜덤 색상
- 랜덤 등장 규칙

주제:

- 매번 다른 값이 나오는 이유 읽기
- 랜덤 위치와 화면 결과 연결
- 랜덤 범위 수정
- 랜덤 등장 결과 예측

학습 목표:

- 매번 다른 결과가 나오는 이유를 코드 기준으로 설명할 수 있다.
- 랜덤 값을 화면 위치, 색상, 등장 위치에 연결할 수 있다.
- 랜덤 범위를 잘못 준 코드를 읽고 수정할 수 있다.

운영 메모:

- `랜덤 모듈 이론 수업`이 아니라 `왜 값이 매번 달라지는지 읽고 고치는 응용 문제`로 운영한다.
- 문제 유형은 값 범위 수정, 랜덤 위치 보정, 결과 예측 중심으로 설계한다.

### 8주차: 시간 모듈 응용

범위:

- 시간 기반 처리
- 제한시간
- 일정 간격 동작
- 시간 차이 비교
- 카운트다운 또는 주기적 등장

주제:

- 너무 빠르거나 느린 동작 읽기
- 시간 간격 수정
- 제한시간 규칙 해석
- 시간 기반 등장 문제

학습 목표:

- 시간이 흐른다는 조건이 화면 동작에 어떻게 연결되는지 설명할 수 있다.
- 너무 빠르거나 느리게 동작하는 코드를 시간 기준으로 수정할 수 있다.
- 제한시간, 대기시간, 등장 주기를 문제 안에서 해석할 수 있다.

운영 메모:

- `시간 모듈 설명`보다 `왜 너무 자주 또는 너무 늦게 동작하는지 찾는 문제` 중심으로 운영한다.
- 랜덤과 섞기 전에 시간 규칙만으로 성립하는 응용 문제를 먼저 다룬다.

### 9주차: 삼각함수 응용

범위:

- `sin`
- `cos`
- 각도와 좌표
- 원운동
- 진동 움직임

주제:

- 원형 경로 읽기
- 진동 움직임 읽기
- 각도와 좌표 변화 연결
- 반지름과 속도 수정

학습 목표:

- 삼각함수가 좌표 변화로 이어지는 방식을 설명할 수 있다.
- 원형 또는 파동형 움직임이 왜 그렇게 보이는지 코드 기준으로 해석할 수 있다.
- 각도, 반지름, 속도 값을 바꿨을 때 결과가 어떻게 달라지는지 예측할 수 있다.

운영 메모:

- 수학 공식 암기보다 `움직임이 왜 이런 경로를 그리는지`를 읽는 응용 문제 중심으로 운영한다.
- 에임, 회전, 궤적 문제의 기초로 연결할 수 있게 설계한다.

### 10주차: 클래스 구조화 응용

범위:

- `class`
- 속성/메서드
- 플레이어/적/탄환 같은 객체 묶기
- 상태 관리 정리
- 긴 코드를 역할별로 나누기

주제:

- 흩어진 변수와 기능 정리
- 역할별 코드 묶기
- 상태와 동작의 연결 정리
- 긴 코드 구조 읽기

학습 목표:

- 왜 변수를 흩어놓는 코드가 관리하기 어려운지 설명할 수 있다.
- 같은 동작을 묶어 클래스로 정리한 코드와 그렇지 않은 코드를 비교할 수 있다.
- 기존에 배운 랜덤, 시간, 이동, 입력 처리를 클래스 구조 안에서 읽을 수 있다.

운영 메모:

- 객체지향 이론 강의가 아니라 `길어진 코드를 정리하는 방법`으로 설명한다.
- 새 기능을 많이 추가하기보다, 앞서 다룬 기능을 구조화하는 응용 문제로 설계한다.

현재 커리큘럼에서는 아래처럼 재배치합니다.

즉, `round01`은 하나의 긴 단일 세트가 아니라
초기 3주를 설계할 때 참고하는 원본 문제 묶음으로 해석합니다.

## 제작 기준

각 주차는 아래 산출물을 기준으로 제작합니다.

- `lesson/`: 해당 주차 운영 안내
- `interactive/`: 웹 풀이용 응용 문제 세트
- `worksheets/`: 출력용 문제지와 정답
- `problem_review_*.md`: 검수 원본

핵심은 모든 주차를 같은 형식으로 반복 생산하는 것입니다.
즉, 매번 완전히 새로운 수업 문서를 만드는 것이 아니라
같은 문제 포맷 안에서 주제만 바꿔 확장하는 방식으로 관리합니다.

초기 6주 운영에서는 아래 항목을 후순위로 둡니다.

- 긴 개념 강의
- 독립적인 객체지향 이론 설명

- 결과 예측과 설명
