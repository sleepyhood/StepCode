# Pygame Round01 mission01~08 예제 파일 설계서

## 문서 목적

이 문서는 `응용수업_실습형_초안.md`를 실제 실행 파일로 바꾸기 전에,
각 미션 파일이 어떤 상태로 제공되어야 하는지 미리 고정하기 위한 설계서입니다.

핵심은 아래 4가지를 먼저 정하는 것입니다.

1. 학생이 처음 실행했을 때 무엇을 보게 할 것인가
2. 학생이 어떤 실험을 하게 할 것인가
3. 버그가 있다면 어느 수준까지 숨길 것인가
4. 학생이 수정해야 하는 범위를 어디까지 허용할 것인가

---

## 공통 설계 원칙

### 1. 파일 난이도 원칙

- 한 파일에 핵심 목표는 1개만 둔다.
- 한 파일에 버그는 가능하면 1개만 둔다.
- 버그 없는 실험형 파일과 버그 수정형 파일을 섞는다.
- 처음부터 빈 파일을 주지 않는다.
- 학생은 "완성"보다 "관찰과 부분 수정"에 시간을 써야 한다.

### 2. 코드 길이 원칙

- 초보 학생이 3분 안에 전체 구조를 훑을 수 있는 길이로 유지한다.
- 반복되는 장식 코드는 줄인다.
- 수업 목표와 무관한 문법은 넣지 않는다.

### 3. 파일 구조 원칙

모든 미션 파일은 가능한 한 아래 구조를 유지합니다.

```python
import ...

pygame.init()
SURFACE = pygame.display.set_mode(...)
pygame.display.set_caption(...)
FPSCLOCK = pygame.time.Clock()   # 필요한 경우만 사용

def main():
    ...
    while True:
        for event in pygame.event.get():
            if event.type == QUIT:
                pygame.quit()
                sys.exit()

        ...
        pygame.display.update()
        FPSCLOCK.tick(...)

if __name__ == '__main__':
    main()
```

### 4. 학생 수정 범위 표시 원칙

- 교사용 원본에는 `수정 허용 범위`를 명시한다.
- 학생용 파일에는 `# 실험 1`, `# 실험 2`, `# 수정 미션` 정도의 짧은 주석만 둔다.
- 한 파일 안에서 학생이 바꾸는 숫자, 한 줄, 한 블록을 구분해 준다.

### 5. 파일 배포 원칙

각 미션은 가능하면 아래 3가지 중 하나로 배포합니다.

- `normal`: 관찰과 숫자 실험용
- `bug`: 고장난 버전 수정용
- `challenge`: 규칙 변경용

필요한 경우 한 미션에 파일 2개를 둡니다.
예: `mission03_update_normal.py`, `mission03_update_bug.py`

## mission01_window.py

### 수업 역할

- 창 크기와 배경색을 직접 바꾸며 `set_mode`, `fill`을 체득하는 입문 실험 파일

### 파일 목적

- 창 크기 숫자가 어떤 방향으로 화면에 반영되는지 확인
- RGB 숫자와 화면 색의 관계 확인

### 시작 상태

- 정상 실행되는 파일
- 기본 창 크기 `(400, 300)`
- 기본 배경색 `(255, 255, 255)`
- 종료 기능 포함

### 학생이 처음 보는 화면

- 흰색 배경의 기본 창 1개

### 학생 활동

- 창 크기 바꾸기 2회 이상
- 배경색 바꾸기 2회 이상
- 최종 마음에 드는 조합 만들기

### 학생 수정 허용 범위

- `set_mode((...))` 숫자
- `SURFACE.fill((...))` 숫자
- `set_caption(...)` 제목

### 숨기지 말아야 할 점

- 코드가 너무 빈약하면 학생이 "그냥 숫자놀이"라고 느낄 수 있으니,
  창 제목 한 줄과 종료 처리까지는 포함한다.

### 금지 요소

- 버그 넣지 않음
- 도형, 이미지, 텍스트는 넣지 않음

### 예상 소요 시간

- 10~12분

## mission02_draw_order.py

### 수업 역할

- 같은 화면에 여러 요소를 그릴 때 `나중에 그린 것이 위에 보인다`를 체감하는 실험 파일

### 파일 목적

- 그리기 순서와 위치를 이해하게 함
- 이후 이미지, 캐릭터, UI 배치의 기초 감각 형성

### 시작 상태

- 정상 실행되는 파일
- 배경 + 도형 2개 또는 이미지 2개가 겹칠 수 있는 구조
- 기본 위치는 일부만 겹치게 설정

### 학생이 처음 보는 화면

- 서로 일부 겹쳐진 두 개의 요소

### 학생 활동

- 두 요소를 완전히 겹치게 만들기
- `blit` 또는 draw 순서를 바꾸기
- 무엇이 맨 위에 보이는지 기록하기

### 학생 수정 허용 범위

- 두 객체의 위치 좌표
- 그리기 순서 2줄

### 권장 구현 방식

- 이미지보다 도형이 더 단순하면 도형으로 먼저 구성
- 이미지 파일 준비가 되어 있다면 이미지 버전으로 확장 가능

### 금지 요소

- 이벤트 기반 상호작용 넣지 않음
- 버그 파일로 만들지 않음

### 예상 소요 시간

- 10~13분

## mission03_quit_bug.py

### 수업 역할

- 이벤트 처리의 필요성을 "창이 안 닫힘" 현상으로 느끼게 만드는 버그 수정 파일

### 파일 목적

- `for event in pygame.event.get():`의 역할 확인
- `QUIT` 검사 구조 확인

### 시작 상태

- 고장난 파일
- 창은 열리지만 X 버튼으로 닫히지 않음

### 학생이 처음 보는 화면

- 배경색만 있는 창
- X 버튼을 눌러도 반응이 없거나 정상 종료가 되지 않음

### 버그 방식

- 이벤트 반복문 자체가 빠져 있거나
- `QUIT` 비교가 잘못되어 있음

권장 방식은 아래 둘 중 하나만 사용합니다.

1. `for event in pygame.event.get():`가 없음
2. `if event.type == QUIT:` 대신 잘못된 타입 비교 사용

### 학생 활동

- 현상 기록
- 의심되는 줄 찾기
- 한 줄 또는 한 블록 수정
- 재실행 후 종료 확인

### 학생 수정 허용 범위

- 이벤트 처리 블록만 수정

### 금지 요소

- 동시에 `display.update()`도 빠뜨리지 않음
- 여러 버그를 섞지 않음

### 예상 소요 시간

- 12~15분

## mission04_update_bug.py

### 수업 역할

- 화면 갱신 함수의 존재 이유를 직접 보게 만드는 버그 수정 파일

### 파일 목적

- `pygame.display.update()`의 필요성 확인
- 화면 변화와 코드 실행의 차이 이해

### 시작 상태

- 고장난 파일
- 내부 값이나 색은 바뀌지만 창에 변화가 거의 보이지 않음

### 학생이 처음 보는 화면

- 화면이 멈춘 것처럼 보이거나 기대한 변화가 안 보이는 창

### 버그 방식

- `pygame.display.update()`가 빠져 있음

### 학생 활동

- 정상처럼 보이지 않는 이유 관찰
- 빠진 줄 추정
- 줄 복구
- 다시 실행해 수정 전후 차이 기록

### 학생 수정 허용 범위

- `pygame.display.update()` 한 줄 복구

### 권장 구현 방식

- 색이 주기적으로 바뀌는 예제
- 카운터가 증가하는 예제
- 둘 중 하나만 선택

### 금지 요소

- FPS 버그와 같이 섞지 않음

### 예상 소요 시간

- 10~12분

## mission05_fps_test.py

### 수업 역할

- `Clock.tick()` 값을 직접 바꿔 가며 속도를 비교하는 실험 파일

### 파일 목적

- FPS의 체감 차이 이해
- "숫자가 커질수록 빠르다"를 실제 화면으로 연결

### 시작 상태

- 정상 실행되는 파일
- 카운터, 이동하는 도형, 깜빡이는 색 중 하나가 계속 변함
- `FPSCLOCK.tick(60)` 포함

### 학생이 처음 보는 화면

- 일정 속도로 움직이거나 변하는 화면

### 학생 활동

- `tick(1)`, `tick(10)`, `tick(60)`, `tick(120)` 비교
- 가장 보기 좋은 값 선택
- 이유 기록

### 학생 수정 허용 범위

- `tick(...)` 숫자만 수정

### 권장 구현 방식

- 단순 카운터 텍스트 또는 좌우 이동 사각형

### 금지 요소

- 버그 파일로 만들지 않음
- 좌표 실험과 섞지 않음

### 예상 소요 시간

- 8~10분

## mission06_shape_lab.py

### 수업 역할

- 좌표, 크기, 선 굵기를 오래 만져 보게 하는 도형 실험 파일

### 파일 목적

- x, y, width, height 개념 확인
- 선 굵기와 채우기 차이 확인
- 좌표계를 화면 감각으로 익히게 함

### 시작 상태

- 정상 실행되는 파일
- 사각형 2개, 원 1개 정도 포함
- 일부 도형이 다소 어색하게 배치되어 있음

### 학생이 처음 보는 화면

- 겹치거나 정렬이 어색한 도형 화면

### 학생 활동

- 도형 위치 이동
- 크기 변경
- 선 굵기 바꾸기
- 도형이 겹치지 않도록 다시 배치

### 학생 수정 허용 범위

- 각 도형의 좌표
- 가로, 세로 길이
- 선 굵기
- 색상

### 권장 구현 방식

- `pygame.draw.rect`
- `pygame.draw.circle`
- 필요하면 `Rect(...)` 형태 하나 포함

### 금지 요소

- 충돌 판정 넣지 않음
- 키보드 이동 넣지 않음

### 예상 소요 시간

- 12~15분

## mission07_image_rotate.py

### 수업 역할

- 회전 이미지가 화면 밖으로 밀려나는 버그를 중심 회전으로 고치게 하는 핵심 디버깅 파일

### 파일 목적

- 회전 결과 이미지의 크기와 기준점 차이 이해
- `get_rect()`와 `center`의 역할 이해

### 시작 상태

- 고장난 파일
- 이미지가 회전은 되지만 왼쪽 위 기준으로 돌아 화면 밖으로 밀려남

### 학생이 처음 보는 화면

- 회전 중 이미지가 화면 안에 안정적으로 머물지 못하는 장면

### 버그 방식

- 회전한 이미지를 `(0, 0)` 또는 고정 좌표로 바로 `blit`
- 중심 rect 재설정 없음

### 학생 활동

- 문제 현상 관찰
- 왜 밀려나는지 말로 설명
- `get_rect()`와 `center` 설정 방식으로 수정
- 중심 좌표를 다시 바꿔 가며 비교

### 학생 수정 허용 범위

- 회전 후 그리는 2~3줄
- 중심 좌표 값

### 준비물

- 배경이 단순한 png 이미지 1개

### 금지 요소

- FPS 실험과 결합하지 않음
- 추가 회전 효과를 너무 많이 넣지 않음

### 예상 소요 시간

- 15분

## mission08_paint_lab.py

### 수업 역할

- 1주차 원본의 그림판 예제를 응용해, 입력 규칙을 직접 바꾸게 하는 가장 긴 실습 파일

### 파일 목적

- `MOUSEMOTION` 이해
- "내가 원하는 동작 규칙"을 코드로 바꾸는 첫 경험 제공

### 시작 상태

- 부분적으로 불편한 정상 파일
- 마우스를 움직이기만 해도 그림이 그려짐

### 학생이 처음 보는 화면

- 클릭 여부와 상관없이 선 또는 점이 계속 남는 그림판

### 핵심 문제

- 학생이 원하는 것은 "클릭할 때만 그리기"인데 현재 규칙은 그렇지 않음

### 학생 활동

- 현재 불편한 점 관찰
- 원하는 동작을 문장으로 먼저 적기
- 클릭 중에만 그리도록 수정
- 추가로 색 또는 점 크기 바꾸기

### 학생 수정 허용 범위

- 이벤트 조건 블록
- 점 색상
- 점 크기

### 권장 구현 방식

아래 중 하나를 선택합니다.

1. `MOUSEMOTION` + 마우스 버튼 상태 사용
2. `MOUSEBUTTONDOWN`, `MOUSEBUTTONUP`으로 그리기 상태 변수 사용

수업적으로는 2번이 더 좋습니다.
학생이 "그리고 있는 중인가"를 상태로 다루는 감각을 처음 가질 수 있기 때문입니다.

### 금지 요소

- 지우개 기능까지는 넣지 않음
- 색상 선택 UI는 넣지 않음
- 파일 저장 기능은 넣지 않음

### 예상 소요 시간

- 18~20분

## 미션 간 연결 설계

각 미션은 독립 실행이 가능해야 하지만, 개념은 아래처럼 이어집니다.

1. `mission01`: 창과 배경
2. `mission02`: 그리기 순서
3. `mission03`: 이벤트 처리
4. `mission04`: 화면 갱신
5. `mission05`: 속도와 프레임
6. `mission06`: 좌표와 도형
7. `mission07`: 이미지 회전과 중심
8. `mission08`: 입력 규칙 변경

즉 앞쪽은 기초 감각, 중간은 디버깅, 뒤쪽은 응용 수정으로 올라가는 구조입니다.

## 다음 작업 권장 순서

이 설계서 다음에는 아래 순서로 진행하는 것이 가장 안전합니다.

1. 미션 파일 8개의 실제 코드 초안 작성
2. 각 파일을 실행해 난이도와 버그 수 검수
3. 그 다음 학생용 활동지 md 작성

학생용 활동지는 반드시 실제 미션 파일의 동작을 기준으로 써야 합니다.
그래야 문항이 뜬구름이 되지 않고, 학생이 실제로 한 행동과 기록지가 정확히 맞물립니다.
