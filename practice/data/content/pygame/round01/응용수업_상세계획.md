# Pygame 1주차 응용수업 상세 계획

## 1. 수업 성격

이 회차는 `문제 풀이 수업`이 아니라 `실행 기반 실습 수업`으로 운영합니다.
학생은 문제를 읽고 바로 답을 쓰는 것이 아니라, 반드시 프로그램을 실행하고 현상을 관찰한 뒤에 답해야 합니다.

핵심 원칙은 아래 3가지입니다.

1. 실행 전 예측이 먼저 나온다.
2. 실행 후 관찰 기록이 반드시 남는다.
3. 수정 뒤에는 재실행 검증까지 완료한다.

## 2. 이번 회차의 목표

- 지난 시간에 만든 pygame 창의 기본 구조를 다시 읽는다.
- 이벤트 처리, 화면 갱신, 그리기 순서의 역할을 실험으로 확인한다.
- 고장난 코드를 직접 수정하고, 수정 전후 차이를 설명한다.
- 규칙 하나를 바꾸며 "배운 개념을 새 상황에 적용"한다.

## 3. 회수할 핵심 개념

- 창 생성과 화면 크기
- 배경색 채우기
- 이벤트 반복 처리
- 종료 조건 확인
- 화면 업데이트
- 그리기 순서
- 좌표와 이동값

이번 회차에서는 새 문법을 많이 추가하지 않습니다.
대신 이미 본 개념을 실제 동작과 연결해서 다시 묻습니다.

## 4. 운영 방식

### 4-1. 50분 권장 배분

- 10분: 실행 전 예측과 코드 읽기
- 15분: 실행 후 관찰 기록
- 15분: 버그 수정과 재실행
- 7분: 규칙 변경 미션
- 3분: 회고와 체크리스트

### 4-2. 진행 원칙

- 모든 문항은 학생이 직접 실행해 본 결과를 적게 한다.
- 교사는 정답 한 줄보다 "왜 그렇게 바꿨는지"를 우선 확인한다.
- 한 문제에 버그를 여러 개 넣지 않는다.
- 수정 포인트는 한 번에 하나만 준다.
- 기능 변경도 한 번에 한 규칙만 바꾸게 한다.

## 5. 문항 설계 원칙

### 5-1. 금지할 구성

- 정의만 묻는 객관식
- 코드를 보지 않고도 찍을 수 있는 문제
- 정답만 베껴 쓰면 끝나는 빈칸형 문제
- 버그가 너무 많아서 초보가 어디서 시작해야 할지 모르는 문제

### 5-2. 반드시 넣을 구성

- 실행 전 예상 쓰기
- 실행 후 실제 현상 기록
- 원인 줄 찾기
- 수정 내용 기록
- 수정 후 변화 설명
- 규칙 변경 결과 기록

### 5-3. 답안 형식

각 문항의 답은 가능하면 아래 요소를 포함합니다.

- 실행 전 예상
- 실제 실행 결과
- 수정한 줄 또는 바꾼 요소
- 수정 후 달라진 점
- 이유 설명 한 문장

## 6. 문제 구성안

이번 세트는 총 8문항으로 구성합니다.
흐름은 `예측 -> 관찰 -> 수정 -> 확장 -> 회고`입니다.

### Q1. 실행 전 예측

- 목적: 학생이 코드를 읽고 화면 결과를 먼저 상상하게 만든다.
- 활동: 창 크기, 배경색, 종료 가능 여부, 화면 변화 여부를 예상해 적는다.
- 실습 필요성: 실행 전 예상이 있어야 뒤의 비교가 가능하다.
- 채점 포인트: 근거를 코드의 특정 요소와 연결했는가

### Q2. 실행 후 관찰 기록

- 목적: 예측과 실제 결과의 차이를 스스로 발견하게 만든다.
- 활동: 프로그램을 실행하고 실제로 보인 현상 2개 이상 기록
- 예시 관찰 요소: 창 크기, 배경색, 마우스/키보드 반응, 종료 버튼 반응
- 채점 포인트: 추상적인 감상 대신 실제 현상을 썼는가

### Q3. 그리기 순서 실험

- 목적: 나중에 그린 이미지가 위에 보인다는 사실을 체감하게 만든다.
- 활동: 같은 위치에 겹친 요소를 실행해 보고, 무엇이 위에 보이는지 기록
- 추가 요구: 그 순서가 바뀌면 화면이 어떻게 달라질지도 예측
- 채점 포인트: "먼저 그린 것/나중에 그린 것"을 구분해서 설명했는가

### Q4. 이벤트 처리 버그 찾기

- 목적: 이벤트 반복문이 왜 필요한지 이해하게 만든다.
- 활동: 종료가 안 되는 버전을 실행한 뒤, 어떤 입력이 무시되는지 기록
- 답안 요구: 의심되는 위치와 이유 서술
- 채점 포인트: 현상과 코드 구조를 연결했는가

### Q5. 이벤트 처리 버그 수정

- 목적: 단순 발견에서 끝나지 않고 실제 수정까지 하게 만든다.
- 활동: 한 줄 또는 한 블록을 고쳐 정상 종료되게 만든다.
- 검증: 수정 후 직접 종료 버튼을 눌러 결과 확인
- 채점 포인트: 수정 전후 차이를 명확히 적었는가

### Q6. 화면 갱신 실험

- 목적: `display.update()`의 필요성을 눈으로 확인하게 만든다.
- 활동: 화면 갱신이 없는 버전을 실행하고 보이는 문제를 적는다.
- 추가 요구: 갱신을 다시 넣은 뒤 무엇이 달라졌는지 비교
- 채점 포인트: "코드가 돌지만 화면에는 반영되지 않음"을 설명했는가

### Q7. 규칙 변경 미션

- 목적: 기존 코드를 그대로 복원하는 것이 아니라 일부 규칙을 바꾸게 만든다.
- 활동: 아래 중 하나를 선택해 수정
- 선택 예시: 점수 10점 이상이면 속도 증가, 배경색 변경, 이동 속도 변경, 벽에 닿으면 멈춤
- 채점 포인트: 바꾼 규칙이 실제 실행에서 확인되는가

### Q8. 회고

- 목적: 오늘 한 수정이 어떤 개념과 연결되는지 정리하게 만든다.
- 활동: 오늘 바꾼 줄 1개, 그 줄의 역할, 다음에 비슷한 문제가 나오면 어디를 먼저 볼지 작성
- 채점 포인트: 단순 감상이 아니라 디버깅 기준이 드러나는가

## 7. 교사용 체크리스트

- 학생이 직접 실행했는지 확인했는가
- 실행 전 예측을 먼저 쓰게 했는가
- 관찰 기록이 실제 현상 중심인가
- 수정 후 재실행을 했는가
- "왜 그렇게 고쳤는가"를 말하게 했는가
- 기능 변경이 실제로 적용됐는지 확인했는가

## 8. 난이도 조절안

### 하위권 학생

- 예측 항목 수를 줄인다.
- 버그 위치 후보를 2~3개로 좁혀 준다.
- 규칙 변경은 숫자 한 개 바꾸는 수준으로 제한한다.

### 중위권 학생

- 버그 위치를 직접 찾게 한다.
- 수정 이유를 말로 설명하게 한다.
- 규칙 변경 뒤 실행 결과 캡처 또는 관찰 기록을 남기게 한다.

### 상위권 학생

- 같은 코드에서 두 번째 변형 규칙까지 시도하게 한다.
- 수정 이유를 "변수/이벤트/화면 갱신" 관점으로 분류하게 한다.
- 수정 전후를 비교해 일반화 문장으로 정리하게 한다.

## 9. 이후 회차 확장 방식

`round02`, `round03`도 같은 틀을 유지합니다.

- 홀수 회차: 제작 중심
- 짝수 회차: 실행 기반 응용 중심

짝수 회차의 기본 골격은 계속 아래 순서를 유지합니다.

1. 실행 전 예측
2. 실행 후 관찰
3. 단일 버그 수정
4. 재실행 검증
5. 규칙 1개 변경
6. 회고

이렇게 고정해 두면 게임 주제가 바뀌어도 수업 운영 방식은 흔들리지 않습니다.
