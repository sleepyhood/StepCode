# Pygame 1주차 응용수업 실습형 초안

## 수업 개요

- 대상 시간: 1시간 30분
- 수업 성격: 읽기형 문제풀이가 아니라 `실행 -> 관찰 -> 수정 -> 재실행` 중심 실습
- 전제: 학생은 1회차 원본에서 아래 내용을 이미 한 번 본 상태
- 사용 범위: `pygame.init`, `set_mode`, `set_caption`, `fill`, `QUIT`, `pygame.event.get`, `display.update`, `Clock.tick`, 좌표, 도형 그리기, 이미지 띄우기, 회전, `MOUSEMOTION`

## 이번 초안의 핵심 원칙

1. 문제를 읽고 바로 답할 수 없게 만든다.
2. 모든 미션에 최소 1번 이상의 실행이 들어간다.
3. 학생이 직접 바꿔 본 값과 결과를 적게 한다.
4. 한 번에 여러 버그를 주지 않는다.
5. 마지막에는 반드시 "내가 바꾼 코드가 어떤 역할을 했는가"를 말하게 한다.

## 미션 1. 창 크기와 배경색 실험

### 목표

- `set_mode`와 `fill`이 실제 화면에 어떤 영향을 주는지 체감한다.

### 학생 활동

1. 제공된 파일을 읽고 창 크기와 배경색을 먼저 예상한다.
2. 코드를 실행해 실제 화면을 확인한다.
3. 창 크기 숫자 2개를 바꿔 본다.
4. RGB 값을 2번 이상 바꿔 본다.
5. 가장 마음에 든 조합 1개를 기록한다.

### 활동지 문항

1. 실행 전, 창의 가로와 세로 크기를 예상해 쓰시오.
2. 실행 전, 배경색이 어떤 색일지 예상해 쓰시오.
3. 실행 후 실제 결과는 어땠는가.
4. `(가로, 세로)` 값을 두 번 바꿔 보고, 창이 어떻게 달라졌는지 각각 적으시오.
5. RGB 값을 두 번 바꿔 보고, 어떤 숫자가 어떤 색 변화를 만들었는지 적으시오.
6. 본인이 선택한 최종 창 크기와 색 조합을 적으시오.

### 시간

- 12분

### 실습이 필요한 이유

색과 크기는 말로만 이해하면 금방 잊는다.
숫자를 직접 바꾸고 화면 변화를 봐야 `앞 숫자는 가로`, `뒤 숫자는 세로`, `RGB는 색의 세기`라는 감각이 남는다.

## 미션 2. 종료 버튼과 이벤트 처리 관찰

### 목표

- `for event in pygame.event.get():`와 `QUIT`가 왜 필요한지 확인한다.

### 학생 활동

1. 정상 버전과 버그 버전을 각각 실행한다.
2. 어떤 버전에서 X 버튼이 먹히고, 어떤 버전에서 안 먹히는지 비교한다.
3. 코드에서 차이가 나는 줄을 찾는다.
4. 버그 버전을 직접 고친 뒤 다시 실행한다.

### 활동지 문항

1. 정상 버전에서 X 버튼을 눌렀을 때 어떤 일이 일어났는가.
2. 버그 버전에서 X 버튼을 눌렀을 때 어떤 일이 일어났는가.
3. 두 코드의 차이가 있는 줄을 표시하시오.
4. 왜 그 줄이 없으면 종료가 되지 않는다고 생각하는가.
5. 직접 수정한 뒤, 수정 전과 후의 차이를 2문장으로 적으시오.

### 시간

- 13분

### 실습이 필요한 이유

이 문항은 코드를 읽기만 해서는 약하다.
실제로 X 버튼을 눌러 보고 "반응 없음"을 체험해야 이벤트 처리의 역할이 기억에 남는다.

## 미션 3. 화면 갱신이 빠지면 생기는 문제

### 목표

- `pygame.display.update()`가 화면에 결과를 반영하는 단계라는 점을 이해한다.

### 학생 활동

1. 화면 색이 계속 바뀌는 정상 버전을 실행한다.
2. `update()`가 빠진 버전을 실행한다.
3. 두 화면의 차이를 관찰한다.
4. 빠진 코드를 다시 넣고 재실행한다.

### 활동지 문항

1. 정상 버전에서는 화면이 어떻게 변했는가.
2. `update()`가 없는 버전에서는 어떤 현상이 보였는가.
3. 코드가 돌고 있어도 화면에 변화가 안 보이는 이유를 자기 말로 설명하시오.
4. 수정 후 다시 실행했을 때 무엇이 달라졌는가.

### 시간

- 12분

### 실습이 필요한 이유

이 개념은 설명만 들어서는 체감이 약하다.
"코드는 실행되는데 화면은 안 바뀐다"를 직접 봐야 update의 필요성이 선명해진다.

## 미션 4. FPS 바꾸기 실험

### 목표

- `Clock.tick()` 숫자가 화면 변화 속도에 영향을 준다는 점을 체험한다.

### 학생 활동

1. 카운터 또는 움직이는 객체가 있는 예제를 실행한다.
2. `tick(1)`, `tick(10)`, `tick(60)`, `tick(120)`으로 바꿔 본다.
3. 각 숫자에서 화면이 얼마나 빠르게 변하는지 비교한다.
4. 가장 보기 편한 값 하나를 고르고 이유를 적는다.

### 활동지 문항

1. `tick(1)`일 때 화면 변화는 어땠는가.
2. `tick(60)`일 때는 어떻게 달라졌는가.
3. 값이 커질수록 어떤 변화가 있었는가.
4. 본인이 선택한 적절한 FPS 값과 그 이유를 적으시오.

### 시간

- 10분

### 실습이 필요한 이유

FPS는 숫자 정의만 외우면 아무 의미가 없다.
느림, 보통, 빠름을 직접 비교해야 `프레임` 개념이 현실 감각으로 연결된다.

---

## 미션 5. 도형 좌표 실험

### 목표

- 좌표, 가로세로 길이, 선 굵기가 도형에 어떻게 반영되는지 이해한다.

### 학생 활동

1. 사각형 2개, 원 1개가 그려지는 파일을 실행한다.
2. 좌표를 바꿔 도형 위치를 이동시킨다.
3. 가로세로 길이를 바꿔 크기를 바꾼다.
4. 선 굵기를 0과 5로 바꿔 본다.
5. 화면에 겹치지 않도록 도형 배치를 다시 설계한다.

### 활동지 문항

1. x좌표를 크게 하면 도형은 어느 방향으로 움직였는가.
2. y좌표를 크게 하면 도형은 어느 방향으로 움직였는가.
3. 선 굵기 0과 5의 차이를 적으시오.
4. 겹치지 않도록 배치한 최종 좌표를 적으시오.
5. 가장 헷갈렸던 숫자 하나와 그 이유를 적으시오.

### 시간

- 15분

### 실습이 필요한 이유

좌표는 눈으로 옮겨 보지 않으면 오래 안 남는다.
학생이 숫자를 직접 바꾸며 움직임을 봐야 좌표계가 몸에 들어온다.

## 미션 6. 이미지 순서와 위치 실험

### 목표

- `blit`의 위치와 그리기 순서가 화면 결과를 바꾼다는 점을 이해한다.

### 학생 활동

1. 두 이미지를 화면에 띄우는 파일을 실행한다.
2. 이미지 위치를 바꿔 서로 겹치게 만든다.
3. `blit` 순서를 바꿔 본다.
4. 어떤 이미지가 위에 보이는지 기록한다.
5. 이미지 일부만 보이게 하는 버전이 있다면 그 영역도 바꿔 본다.

### 활동지 문항

1. 같은 위치에 겹치게 했을 때 맨 위에 보인 이미지는 무엇인가.
2. `blit` 순서를 바꾸자 무엇이 달라졌는가.
3. 위치 값을 바꾸자 이미지가 어느 방향으로 이동했는가.
4. 이미지 일부만 보이도록 한 경우, 어느 부분이 잘려 나왔는지 적으시오.

### 시간

- 13분

### 실습이 필요한 이유

그리기 순서는 말보다 화면이 훨씬 강하다.
순서를 바꿔 보고 겹침 결과를 눈으로 확인해야 나중에 캐릭터, 배경, UI 순서를 다룰 수 있다.

## 미션 7. 회전 이미지 버그 수정

### 목표

- 이미지가 왼쪽 위를 기준으로 돌 때 생기는 문제를 보고, 중심 회전으로 고친다.

### 학생 활동

1. 회전 이미지를 실행해 화면 밖으로 밀려나는 현상을 관찰한다.
2. 왜 그런 현상이 생기는지 그림 또는 말로 설명한다.
3. 중심 좌표를 설정하는 방식으로 수정한다.
4. 수정 후 다시 실행하고 차이를 기록한다.
5. 중심 좌표를 한 번 더 바꿔 보며 회전 중심이 어떻게 달라지는지 확인한다.

### 활동지 문항

1. 수정 전, 이미지가 어떻게 움직였는가.
2. 왜 화면 밖으로 나간다고 생각하는가.
3. 수정 후에는 무엇이 달라졌는가.
4. 중심 좌표를 바꾸자 어떤 변화가 있었는가.
5. 이번 미션에서 가장 중요한 줄이 무엇이었다고 생각하는가.

### 시간

- 15분

### 실습이 필요한 이유

이 미션은 "버그 관찰 -> 원인 이해 -> 수정 검증"의 흐름이 뚜렷하다.
설명만 듣는 것보다 직접 고쳐야 중심 좌표의 의미가 잡힌다.

## 미션 8. 그림판 미션: 클릭할 때만 그리기

### 목표

- `MOUSEMOTION`을 이용한 그림판 코드에서 불편한 점을 찾고, 원하는 규칙으로 바꾼다.

### 학생 활동

1. 기본 그림판 버전을 실행한다.
2. 클릭하지 않아도 그림이 그려지는 문제를 확인한다.
3. 원하는 동작을 먼저 문장으로 적는다.
4. 클릭 중에만 그려지도록 수정한다.
5. 색 또는 점 크기를 한 번 더 바꿔 자신만의 버전으로 만든다.

### 활동지 문항

1. 기본 버전에서 불편했던 점은 무엇인가.
2. 내가 원하는 그림판 규칙을 한 문장으로 적으시오.
3. 수정 후에는 어떻게 동작했는가.
4. 추가로 바꾼 요소 1개와 그 이유를 적으시오.
5. 오늘 만든 것 중 가장 "게임 만들기와 연결된다"고 느낀 기능은 무엇인가.

### 시간

- 20분

### 실습이 필요한 이유

이 미션은 가장 손이 많이 가야 한다.
이벤트를 그냥 읽는 수준이 아니라, 내가 원하는 입력 규칙으로 바꾸는 경험이 있어야 응용 회차의 목적이 살아난다.
